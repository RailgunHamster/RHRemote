## 系统已经显示，应用却报未打开

`ui-control-handle127-review-20261030/full127-light01` 随后失败于系统 IME。此次首帧状态为 8415 ms，没有媒体超时；不把它与此前 122 的首帧失败合并成同一种原因。

相对键盘测试开始，统计记录为：

| 事件 | 时间 | 状态 |
| --- | ---: | --- |
| 请求显示键盘 | 22.425 ms | visible=false |
| 第一次观察 | 191.548 ms | visible=false |
| 观察到键盘已可见 | 2195.581 ms | visible=true |
| 请求以失败结束 | 2300.025 ms | visible=true，error=键盘未打开 |

原 `RhSoftKeyboard.poll` 要求可见状态达到目标且后台显示／动画已稳定。两秒期限到达时，即使已经观察到目标状态，也会因尚未稳定而走失败分支，取消显示并重新展开控制面板。这解释了本轮“可见却报未打开”的具体代码路径；此前 122 的极长主线程迟到仍是另一个保留样本。

preview.128 保持原两秒期限和正常期间的动画等待。在期限到达时，已经观察到目标可见／隐藏状态就确认成功；没有达到目标或无法读取状态时继续失败，并保留本轮显示取消、旧回调隔离及退出清理。没有通过延长超时来记作通过。

新增两个行为用例在旧代码实际失败：已可见仍报未打开并被撤销、已隐藏仍报未关闭。修改后完整 **479** 项 JVM 通过，零失败、零忽略。全部 native `.so` 与 preview.122 逐字节相同，源清单、旧失败 XML 和新回归 XML 位于 `D:\RHRemoteTools\ui-ime-result128-review-20261030`。

preview.128 的 `full128-light01` **未通过**。取得首帧状态为 50086 ms，之后统计记录原生 `-1` 中断并转入恢复；原控件探针未找到模式按钮，尚未执行到 IME。不是此次已可见状态的判断分支失败，也不是新的首帧超时，保留原始失败而不推断全部原因。后续相同参数复验被主机空闲性预检拒绝，没有执行第二轮串流、取消或重启；最后连接记录的归属仍待确认。
