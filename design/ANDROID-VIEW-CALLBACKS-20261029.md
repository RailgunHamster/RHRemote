# Android 设备切换后的旧控件事件

本地 Android preview.87，versionCode 304。Windows 保持 preview.86。证据目录：`D:\RHRemoteTools\ui-form-events87-review-20261029`。未发布，未操作 OPPO。

## 复现和行为

preview.83 已限制旧 RhHome 操作后来创建的 Home，但同一个 Home 中被替换的 View 仍可能分发事件。切换设备后，旧输入连接、保存按钮、路径开关及下拉回调仍然引用当前草稿。被搜索过滤掉的设备行也仍能改变选择。

修改前五个回归都失败：

- 旧 InputConnection 把新设备草稿的码率从 22 改成 64。
- 旧保存按钮提交了后来设备的草稿，页面返回设备页。
- 旧路径开关移除了新设备的局域网路径。
- 旧下拉回调把新设备的 HEVC 改成 AV1。
- 被过滤掉的设备行把当前选择从 host-1 改成 host-0。

`before87-02.log` 和 `before-unit-xml87-02` 保留完整失败。另将同一原生测试运行在旧 preview.85 模拟器 APK 上，也在旧事件误提交、页面由 settings 变成 devices 的断言处失败，见 `native-before85`；随后恢复 preview.87。只操作专用模拟器，原配置由快照恢复。

现在 UI 事件回到主线程后，检查源控件仍属于当前可见的控件树，再调用原共享动作。文本值在排队前复制，避免引用后续变化的 Editable。Home 继续核对 Activity 和当前 Home 归属；设备浏览器也检查按钮／设备行仍在其可见树中。侧栏、表单按钮、文本、开关、下拉、同步间隔和更新取消使用相同规则。

接口仍操作当前页面的有效草稿，不增加新的按钮或确认步骤，也不改变连接参数的保存规则及同步格式。隐藏或移出的旧 View 不再代表当前 UI 操作。

## 验证

完整 Android JVM 回归 **413 项通过**，无失败、错误或跳过，见 `units87.json`。五个新回归同时核对旧事件无影响，以及当前控件仍可提交；保留早先页面重建、确认框、更新、同步及会话回归。

专用 emulator-5580 的三种窗口分别为 1512×1008、1008×1512、540×1200，density 240，最后一种字体 1.3；浅深主题共 **六个原生流程**通过。每个流程使用两台专用临时设备，检查：

- 实际列表／设备下拉切换后，调用保留的旧输入连接和旧保存按钮，新设备仍停留在设置页，草稿为 22，持久数据指纹未变。
- 当前原生 InputConnection 可把码率改为 24／23，当前保存按钮只保存目标设备，源设备原值保持不变。
- 旧路径开关和旧选择回调不改变当前草稿；当前开关／下拉确实改变草稿，取消后放弃这些临时修改。
- 被过滤掉的旧设备行不改变选择或查询，当前可见设备行可正常选择。

六个样本中，直接调用旧原生 InputConnection 的 commitText 均返回 true，应用草稿和保存值仍不变。这是应用内调用原生对象的生命周期测试，不等于系统输入法 Binder 路由、物理触屏或 OPPO 实测。没有使用 computer use、OS 输入或 OS 截图，没有发起串流、配对或 WebDAV 同步；正常设备发现仍沿用既有机制。

`native-matrix87.json` 汇总六个流程。图像由本应用自身 View.draw 导出；临时设备是明确的测试数据，不当作日常三台电脑的配置预览。各轮结束等待自有 Activity 销毁，再恢复完整共享文件、偏好和原备份目录。
