# Windows 长保存错误与固定操作栏

2026-11-01，本地 Windows 源码／Release 编译版本 preview.184。连接设置和 WebDAV 设置的长错误说明限制在 80 个逻辑像素高的独立滚动区域内，完整原文保留，保存和取消继续固定。Android 源码保持 183，本轮没有替换日常客户端或发布。

## 已确认的问题

旧 172 在八组受控长错误场景中，保存按钮均位于窗口之外；720×560 的一组保存按钮纵坐标为 2933。错误文字直接参与固定底栏的布局，正文最低只剩 50 个逻辑像素。这里检查的是异常文本长度下的布局缺陷，不是用户主机自然发生的服务端故障记录。

连接设置的长详情在视图边界注入，实际 Controller 的无效帧率草稿仍保留；WebDAV 错误通过自有 Platform 边界进入真实 Controller 保存失败路径。两类范围分别记录，不能把前者描述成实际操作系统写盘失败。

## 行为

- 错误区按内容决定高度，最多 80；更多文字可用滚轮、触控板或键盘阅读。不是截断错误字符串。
- 原正文和操作栏继续显示。新错误从开头显示，重复设置同一错误值保留滚动位置。
- 长错误区可聚焦；支持上下方向键、PageUp／PageDown、Home／End。应用测试接口和 PowerShell 工具同步支持两个翻页键。
- 既有保存、取消及未保存决定动作不变。没有增加业务按钮、网络接口、系统按键或窗口激活。

使用 Slint 的[ScrollView](https://docs.slint.dev/latest/docs/slint/reference/std-widgets/views/scrollview/)显示完整内容；可见尺寸和内容尺寸独立，滚动条不占用文本宽度。应用内焦点和键盘分发沿用当前 UiProbe／KeyboardFocus 规则，确认框期间不接受背景操作。
