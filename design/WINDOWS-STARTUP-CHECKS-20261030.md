# Windows 本地载入、后台检查与启动记录

本轮最终本地候选为 preview.141。完整回归、四组宽窄／主题组件、两轮真实探测暂停及单台检查的最终 Release 副屏验证通过；日常 preview.101 和 Android preview.129 未替换。证据目录沿用最初版本命名：`D:\RHRemoteTools\ui-startup140-review-20261030`。本记录对应客户端 UI 阶段；2026-10-31 用户另行批准的本机／claw 服务更新单独记录，不与这些测试混算。

## 等待来自哪里

此前 run 在创建 MainWindow 和控制接口前调用 devices.restore(probe=true)，顺序探测全部设备；原生 CLI 每台可等待 5 秒，还包含路由查找。本地配置载入和网络认证混在同一步。窗口创建后，轮询线程又立即执行一次完整刷新。139 将手动刷新移出普通队列，但未改变这段窗口前的工作，见[上一轮范围](WINDOWS-REFRESH-QUEUE-20261030.md)。

当前 [run](../client/crates/rhremote-ui/src/lib.rs) 只从本地文件恢复设备，用内部 localOnly 标记跳过 loopback 身份查询及远程探测。Controller 将这些记录标为待检查，先绑定初始界面并请求显示窗口，再启动逐台检查。这消除了窗口必须等网络检查完成的代码依赖，不代表已经缩短远程首帧。

## 未知、配对和逐台可用

[State](../client/crates/rhremote-core/src/lib.rs) 新增 devicesPending；它只属于本机运行状态，不写入 Saved 或 WebDAV。新载入、没有确认记录的设备不再自动显示“未配对”，默认操作为检查连接；检查中该入口禁用。本次运行中已经确认的 paired 事实不会因为一次超时被清掉；已有配对记录仍可显式连接，由既有原生协议继续检查身份。

原生 list 探测的源码为 `D:\RHRemoteTools\moonlight-qt-v6.1-source\app\cli\listapps.cpp`。当前适配的失败退出码同时用于 ComputerSeekTimedout 和 ComputerFound-but-unpaired，不能仅凭非零退出码判断“未配对”。本轮没有修改、编译或替换这个原生引擎。

当原生探测成功或确认是本机时，Controller 接受可确认的观察，并逐台移出待检查列表。未确认的失败保留未知状态；在线但未确认配对的记录另提供显式“配对”，用户可以主动选择，不把检查失败自动变成重新配对。离线、待检查且没有已有配对记录时，连接／配对 API 同样拒绝，界面和后端保持一致。

[DeviceObservation](../client/crates/rhremote-core/src/device_refresh.rs) 通过同一 Platform 接口逐台发布。第一台确认完成后可以连接，不必等待后续设备；检查的取消、前台通道交接仍使用 139 的同一租约。未知观察不覆盖已有 paired，取消或跳过的探测不发布完成事实。

旧结果保护同时用于每次进度回调和最终返回：连接／配对代次变化、设备移除或编辑、对应保存策略变化时，不覆盖当前记录。显示名称使用当前 Saved 中的别名。逐台进度不是不经校验的另一条界面更新通道。

“检查连接”使用 devices.refresh(uuid=选中设备)，工具栏“刷新”省略 uuid、检查列表。参数校验、原生遍历和 Controller 合并都限制该范围，其他设备不会被这次单台检查误标为已验证；动作目录声明了 Windows 的可选 uuid 参数。两个入口也具有不同的参数，应用控件接口可以准确区分。

## 一次按下的操作归属

进度发布会让“检查连接”变成“连接”。旧 ActionButton 在松手时读取最新 action-id，明确复现：按住检查按钮，后台确认配对，松手意外发送 device.connect。

当前按钮记录按下时的动作、参数和文字；它们变化或控件变为不可用时，这次按下失效。需要重新点击当前按钮。切换到另一台设备也不会把旧按下转为连接新设备。键盘和命名控件 API 按当前可用状态执行，不需要伪造鼠标按下。普通连接按钮在仅有后台状态刷新时仍能完成点击。

## 即时启动记录

[Statistics](../client/crates/rhremote-ui/src/statistics.rs) 在测试模式／已启用统计时，为每次启动创建独立 startup-* 目录，逐阶段写 startup.jsonl 和带 appVersion 的 manifest。无需先建立远程连接；关闭统计不再写出新阶段。文件不记录画面、音频、输入内容或凭据，也不加入 WebDAV 配置。

关键事件为 application_start、preferences_loaded、devices_loaded_local、ui_created、ui_initial_view_bound、ui_shown、devices_check_begin、devices_check_end 和 ui_event_loop_returned。ui_shown 表示窗口显示请求，不是物理首屏扫描输出；远程首帧继续由连接统计单独计时。连接时钟的替换不会删除或重复启动阶段。写入错误在 statistics.state.startupError 中可见，不阻止后续界面操作。

已分析的旧记录沿用现有 analysis-complete.json／keep 规则。当前启动及活动连接记录受保护；回归实际发现 Windows canonicalize 添加扩展路径前缀后，原字符串比较无法识别当前启动记录，已按同一种规范化路径比较。

- 启动文件在没有任何连接时可直接读取；写入失败可观察，活动文件不会被清理，连接时钟不会污染启动阶段。
