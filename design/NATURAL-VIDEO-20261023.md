# 预录制影片的局域网 / 中继对照

使用 Blender 的 Big Buck Bunny 1080p30 动画影片，文件来自[官方入口](https://peach.blender.org/download/)指向的[公开素材目录](https://download.blender.org/demo/movies/BBB/)，署名 `(c) Blender Foundation / www.bigbuckbunny.org`。文件元数据为 H.264、1920×1080、30/1 FPS、约 634.6 秒；播放器以正常速度从第 30 秒播放，`-an` 关闭声音。客户端也关闭声音。

用 `tools/natural-video-source.ps1` 启动硬性限时的独立播放器，校验素材 SHA256，并按物理像素检查窗口完全位于已有自有虚拟屏 1920×1080、x=1920、y=0。只读取本次播放器的窗口及进度元数据；测试结束关闭本次进程、删除本次计划任务、恢复虚拟屏 2520×1680，并核对其他屏不变。客户端配置、选中设备、统计及 WebDAV 自动同步均恢复。OPPO 未操作。

两轮使用普通 Windows 客户端 `128cc268`（Rust UI `3256CC35`、Native `7A59114B`），主机为 Rust `2051377` / 引擎 `7332952e`，H.264、请求 1080p30 / 5 Mbps。先中继、后 LAN；LAN 等待播放器进入稳定播放后计时，中继另外分析剔除前 5 秒的窗口。服务器配置 minimum_fps_target=60，渲染次数包含重复帧；未测独特画面呈现频率或物理扫描完成。

两轮均正常结束，记录丢失及组帧帧号缺口均为 0。客户端采样的网络丢帧均为 0%，但中继的短窗口抖动丢帧采样达到 11.11%；这不是全程平均值，也不能写成“没有抖动丢帧”。播放器自身在两次源状态读数间分别增加 16 / 18 次丢帧，播放时间推进与实际经过时间比值约 0.99995 / 1.00001；不把文件 30 FPS 当成实测绘制 30 FPS。

组帧数据来自上游毫秒时间戳，存在时钟粒度误差；表中的 0 ms 不等于没有耗时。解码、渲染调用和渲染间隔由本地高分辨率记录取得，终点仍是 CPU 渲染提交返回。

中继剔除前 5 秒后仍有相同的 62 次渲染间隔超过 50 ms。中继组帧等待达到 94 ms，解码和渲染调用本身很短；局域网相同负载明显更稳。这些证据支持继续定位中继路径中的传输、转发和收包抖动，尚不足以把原因唯一归给 tc 带宽、某个队列或某个客户端线程。不能用增大播放队列来掩盖交互延迟，也没有证据需要重写硬件解码器。

这两轮是有边界的运行对照，完整验收保持未完成：还需更长时间、实际外部运营商/蜂窝网络、网络切换和声音场景。不能据此承诺公网 25 Mbps 或 4K60。
