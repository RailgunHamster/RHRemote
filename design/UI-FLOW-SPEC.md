## 全局规则

1. 同一时刻每个界面只有一个清晰的主要动作；分类导航、状态开关与提交动作视觉区分。
2. 一个按钮只产生一次动作；等待、失败、取消、清理和可重试状态必须可见。
3. 返回恢复原设备与搜索条件。切换分类不提交、不丢失输入；普通返回不等于悄悄放弃设置。
4. 未保存表单离开时给出保存后继续 / 放弃更改 / 继续编辑。保存失败留在对应字段所在分类。
5. 所有控件和确认选项均经共享动作 API；API 和界面的结果一致。
6. 不以缓存在线状态禁止备用地址连接；配置地址、当前选路和已显示画面是不同证据。
7. 不改变用户的配对、画质、声音、WebDAV 和业务服务来换取“界面测试通过”。布局验证使用模拟器；Windows 使用独立预览配置。
8. 用户验收的 Windows 预览从日常设备配置创建副本，保持设备列表、顺序、别名、备用地址和各客户端参数；标题保留测试标识。只含单台设备的故障测试数据不能代替日常列表验收。测试不复制 WebDAV 登录信息或原生配对身份，不自动同步回日常配置。
9. Windows 测试默认只放实体副屏，不自动回退到主屏；用户明确允许当轮使用主屏时，须显式指定已枚举的物理显示器并记录授权，不能以虚拟屏代替。预览保持不激活，不反复抢焦点。业务和控件操作、日志、自身渲染截图走应用接口。原生激活式焦点测试不自动恢复，用户工作期间只做接口与只读检查。[启动与边界](WINDOWS-UIA-20261027.md)
10. 按用户明确要求，不使用 computer use 操作客户端。按钮、表单、导航和确认流程使用现有共享动作及实际控件测试接口；布局使用应用自身渲染图，透明／重绘问题通过渲染和窗口事件定位。接口未覆盖的行为先补接口与证据，不以反复弹窗、抢焦点或系统输入补足验收。
