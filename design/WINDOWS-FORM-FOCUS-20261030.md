# Windows 表单焦点、控件定位与 Release 打包

日常客户端已按用户批准原地升级到 preview.101，保持关闭。配置与旧包备份保留，详见[顶部悬浮按键入口及升级结果](FLOATING-KEYBOARD-ENTRY-20261029.md)。本文的 Windows preview.125 是后续独立候选，未安装到日常目录，也未公开发布；Android 当前仍为 preview.122，未操作 OPPO。

## 实际发现与修正

在实体副屏的独立窗口中，旧版控件接口不能精确区分添加页的两个取消入口，也拒绝设备排序按钮的复合参数。preview.123 为 `view.ui.activate` 增加 inspect 返回的完整 `control` 标识，由实际按钮回调提供参数；保留动作归属、唯一性、模态、可用状态及会话阶段检查。未指定 control 的原有语义查找继续有效，完整规则见[控件接口](UI-TEST-API.md)。六个定向用例及四个实际按钮回调通过，两处取消和排序／还原分别核对。

继续通过实际保存按钮提交非法音量时，复现焦点留在页面而未进入输入框。preview.124 将焦点请求与本次校验、当前草稿关联，每个请求只消费一次。重复校验可以再次聚焦，普通状态刷新、分类离开及编辑器重建不会重新领取旧请求。

补充 720×560 小窗口检查后，发现聚焦仍不代表完整可见：错误提示加入底部后，视口由原尺寸缩小，输入框底部被裁住。增加布局观察后，连续十一帧位置完全相同，排除了只等待一次动画即可解决的解释。Slint 的焦点事件只在取得焦点时执行一次 reveal，随后位置跟踪更新 IME，没有因视口缩小重新显示该字段。

preview.125 在实际视口尺寸变化时显示当前出错且已聚焦的完整输入框；不重复取得焦点，也不监听普通用户滚动来强行拉回位置。没有修改 Slint vendor、增加生产等待时间或放宽校验。

## 回归与实体窗口

证据目录：`D:\RHRemoteTools\ui-form-reveal125-review-20261030`。基线失败分别保留在 `ui-button-selector123-review-20261030` 与 `ui-form-focus124-review-20261030`。

- 完整 Core **136** 项、UI **236** 项通过，另有 **4** 项既有显式验收用例默认忽略。不是全部 workspace 或全部真实服务验收的计数。
- 新增实际控件用例覆盖浅深主题、720×560 与 1180×780、重新校验、后台刷新、切换分类、保存并继续失败后的新目标，以及网络地址错误切换分类。
- 所有当前 Windows 数字编辑项及中继地址在布局完成后完整进入视口；中继地址错误后手动滚回顶部并继续刷新，位置不会被错误显示逻辑拉回。
- preview.124 的普通焦点用例通过，但附加视口检查失败。保留失败包和日志，不将它作为完整表单验收通过的版本。

## 之前的 Debug 打包

旧 preview.110 包内 UI 的 SHA-256 与当时 `target/debug/RHRemote.exe` 完全相同；日常 preview.101 的构建日志也明确为 `dev [unoptimized + debuginfo]`。PE 中仅有 PDB 文件名，不能单靠该字段判断构建目录。

打包脚本现默认执行优化 Release 构建；只有显式 `-ReleaseBuild:$false` 才选择 Debug。preview.124、preview.125 均在省略 ReleaseBuild 参数的情况下成功编译、打包，日志明确为 `release [optimized]`。本轮没有更改普通开发构建脚本的用途。

此前相同 2655×1755 页面导出的短样本如下，原 JSON 的 `completedAtMs - requestedAtMs` 可复核：

| 页面 | Debug preview.110 | Release preview.123 |
| --- | ---: | ---: |
| 最终设备页 | 1974 ms | 160 ms |
| 本机音频设置 | 2000 ms | 77 ms |
| 本机画面设置 | 2130 ms | 138 ms |

这是请求排队、软件绘制及 PNG 导出的总耗时。两版代码及当时系统负载并不完全相同，样本也短；它不是点击延迟、首帧、串流帧率或固定倍数提升的结论。数据见 `render-sample-comparison.json`。
