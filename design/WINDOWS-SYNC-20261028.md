# Windows 同步结果与冲突界面

本地 Windows preview.45。Android 保持 preview.34；未操作 OPPO，未发布、未启动新的 Windows 客户端窗口。完整 UI 目标未完成。

## 原问题与行为

原先“立即同步”和冲突选项位于长表单末尾，冲突区直接显示 `devices.<uuid>` 等内部键。新增 Slint 控件回归在原布局明确失败：同步按钮位于账户输入框下面。现在最近同步状态与操作位于表单上方，冲突显示设备／客户端名称及两端摘要，保留相同的共享动作和明确选择规则。同步期间相关按钮禁用，完成后滚动回结果区；不重建内容相同的冲突行模型。

更重要的问题是上传返回 HTTP 302 时误报成功。HTTP 库在关闭自动重定向后把此响应交给调用者，原代码只检查是否返回错误，没有确认响应状态，随后保存了新的 base 和成功时间。`redirect-before.log` 已复现返回 `Ok(shared...)` 且 `lastSyncMs` 前进。

现在 GET 只接受 200 或用于首次创建的 404；PUT 只接受 2xx。重定向、认证失败及条件写入失败均停止，不跟随新地址，不更新成功时间或合并基线。错误提示区分账户权限、证书／TLS、超时、域名及服务器响应。原强 ETag、条件创建／覆盖、冲突快照新鲜度、备份和凭据存储边界保持。

## 后台验证

证据目录：`D:\RHRemoteTools\ui-windows-sync-review-20261028`。

- `sync-order-before.log`：原布局顺序回归失败。`redirect-before.log`：上传返回 302 仍保存成功状态的明确失败。两份均保留，不改写历史结果。
- `windows45-final-parallel.log`：核心 112／UI 134 项默认并行通过，无失败或跳过；没有用串行替代并行。
- 实际 Windows TCP／TLS 测试使用进程内临时证书和 `rustls` 服务。默认客户端拒绝不受信任的颁发者；仅给测试 Agent 添加此临时信任后，仍拒绝不匹配的主机名。两次服务端均未收到 HTTP 或认证头。正确证书和主机名完成 GET／PUT，并检查实际 JSON 与条件创建头。
- HTTPS GET 返回带有效 JSON、ETag 和可达 Location 的 302 时仍只有一次请求，无 PUT；PUT 412 和 302 均保留原 base、成功时间及本机账户文件，检查实际 `If-Match`。401 显示账户提示。服务端收到 GET 后延迟响应，客户端在测试专用的 5 秒总预算内返回超时，保留原状态；生产总预算仍是 15 秒。
- 测试的信任根只存在于单个 Agent 中；证书／私钥只在内存生成，没有写入系统证书库，也没有关闭主机名校验。Release 使用原默认 Agent；没有新增可绕过信任校验的用户设置。测试用 `rcgen` 只属于 dev-dependencies。
- 中间失败 `sync-tests45.log` 与 `tls-fixture-diagnostics.log` 来自 Windows 上测试服务接受的 socket 继承了 listener 的非阻塞模式。显式切回阻塞并正常发送 TLS close-notify 后，证书、主机名和传输流程通过；这不是生产同步问题的修复证据。`sync-tests45-blocking-fixture.log` 和 `windows45-full-parallel.log` 另保留超时测试预算假设不成立的记录；最终使用真实 GET 到达断言及足够的握手预算，不能把握手前超时算作收到 GET 后的读超时。

## 无窗口布局验证

使用同一份 `app.slint` 和 Slint 的 TestingBackend／真实软件绘制器，创建虚拟 TestingWindow，不创建 Win32 窗口。主题与生产绑定一致，同时设置根界面和全局调色板。首次辅助测试只设置根主题，深色截图的全局颜色不匹配；那些 `headless-software` 图片不计为最终主题证据。最终图仅来自 `headless-software-final`。

1180×780 和 720×560、浅深两种主题各验证冲突、进行中、失败三种状态，共 12 张自身绘制图。检查关键按钮在真实表单视口内完整可见、只分发一次选定范围的共享动作、忙碌时不分发、滚动到底后完成回到结果区，以及固定保存栏保留在窗口内。截图背景还与实际主题调色板核对；已人工检查最终浅深色输出。

这些是相同 UI 控件与绘制代码的后台证据。它们不证明实际 Win32 的焦点、遮挡重绘、双屏 DPI 或软件呈现到物理屏幕；也不等于已经在实际客户端完成真实 WebDAV 账户的端到端同步。没有 computer use、系统输入或屏幕抓取。
