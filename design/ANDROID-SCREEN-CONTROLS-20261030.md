# Android 会话分类：输入与画面分开

本地 preview.129 将“移动画面”“还原缩放”和当前缩放比例移到“屏幕”。“操作”保留点击模式、系统键盘、快捷键、安全注意序列、滚动模式及统计；四个主要输入按钮使用两列布局，窄屏和大字号继续按文字宽度回退。顶部悬浮键盘开关、收起和断开位置不变，声音继续独立。

这沿用此前选定的 HelpWire 会话菜单方向，其[连接选项](https://kb.helpwire.app/operator-application/connection-options/)集中提供画面尺寸与适配操作；RHRemote 保留自己的选屏、触控和滚动功能。本轮只整理已有 Android 功能，不给 Windows 增加未实现的缩放按钮。

## 操作和反馈一起迁移

- “移动画面”“还原缩放”仍调用原 `stream.pan.toggle`／`stream.zoom.reset`，没有修改缩放计算、输入通道、解码或编码。
- 两项结果反馈归属“屏幕”；还原后再次缩放会清除旧成功提示并显示当前比例。隐藏页不更新缩放文字，重新进入时显示最新值。
- 两个按钮不再进入“操作”的 Tab 路径；隐藏控件不能接收保留的旧点击回调。忙碌时仍禁用，保留控制栏及本地导航。
- “屏幕”的新按钮采用与已有按钮相同的动态列宽、边距和滚动正文，不挤入固定页头。

## 验证与保留失败

证据目录：`D:\RHRemoteTools\ui-screen-controls129-review-20261030`。

新增分类归属用例在原布局失败：输入页仍显示画面移动按钮。第一条准备命令工作目录有误，未装入新测试；修正后重跑的 `baseline-test02.log` 及 `baseline-RhStreamPanelTest.xml` 才是有效旧版证据。

第一次完整回归为 481 项、两项失败：原测试的查找函数只返回当前可见页面的按钮，却继续在“操作”查找移走的两项。修正为先切到“屏幕”核对禁用，再返回“操作”核对本地导航；隐藏断言按保留的控件标识检查。原失败 XML 保留，断言未删除。最终完整 **481** 项 JVM 通过，零失败、零错误、零忽略；包含缩放实时更新、隐藏回调拒绝、忙碌期间切页及 Tab 循环。

专用 emulator-5580 使用实际 PcView 窗口、StreamView 和生产 RhStreamPanel，分别运行 100%／200% 字号、浅深主题共 **四个** 原生窗口场景。每组实际确认：

1. 输入页不显示画面变换按钮，旧回调无动作。
2. 屏幕页的两个按钮可各自完整滚动到视口，实际点击分别产生一次原动作。
3. 切到声音页后，旧回调被拒绝；屏幕操作忙碌时两项继续禁用。
4. 每轮恢复十五份配置／身份文件、同步备份、字号及显示尺寸／密度，关闭自有窗口。

原生场景的 connected 状态明确是组件条件，没有 Game、真实首帧、主机选屏或远端输入。不能将它写作真实缩放、外网或完整串流验收。此前 preview.128 的完整串流在出帧后发生原生 `-1` 中断，仍保留调查；preview.129 尚未重跑完整会话。
