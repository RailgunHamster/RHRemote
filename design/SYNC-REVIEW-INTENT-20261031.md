# 同步审阅的等待与操作归属

2026-10-31，本地源码与测试候选 preview.158，接续 [157 的字段对照](SYNC-REVIEW-FIELDS-20261031.md)。完整 UI 目标继续进行。

## 修正的流程

- 正常自动同步计时器原本已在冲突等待时暂停；接口入口与排队执行现在也遵守相同规则。自动请求返回 `skipped:true / reason:sync_conflict`，保留当前审阅与草稿，不启动新任务。`automatic` 参数必须为布尔值，错误类型不再落入手动同步。
- 本机配置、远端配置和 ETag 组成一份审阅快照。相同快照重复检查保留 `reviewId`，任一变化生成新标识。两端保留按钮绑定所显示的标识，入口及后台执行均校验，拒绝旧选择时保留新审阅；仍执行原有数据与 ETag 核对。旧接口省略标识的行为保持兼容，当前界面对有效审阅带上标识。
- Android 一次发布完整、不可变的待审阅对象，状态接口返回独立冲突数组，避免标识与内容分别更新或被调用方改写。后台任务再次检查标识，过期选择在凭据／HTTP 访问前结束。
- 冲突页的手动同步按钮显示“重新同步”，使用次要样式；明确它会执行完整同步，而不是纯读取。Android 同步页使用页内状态及错误区，去掉重复的底部全局状态，改善大字号下的正文空间。
