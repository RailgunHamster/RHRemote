# Android 恢复过程的反馈与取消（preview.40）

旧版本的自动恢复可以成功，但原会话清理会移除控制面板。恢复状态只在 API 中可查，界面没有持续显示阶段和取消入口。新增两项回归在 preview.39 代码上均失败，原因是没有显示恢复提示；原 22 项恢复测试仍通过。旧版本真实串流对照也通过，恢复首帧 3641 ms，因此本次修复的是交互反馈，没有将它描述成恢复算法提速。

## 行为

- 恢复任务持有自己的原生提示框，显示“正在恢复连接”和清理、检查地址、启动串流三个实际阶段。使用现有浅深色弹窗主题，内容可以滚动，取消按钮保留在独立区域。
- “取消连接”、本地 Back／Escape 都走已有 `stream.disconnect` 动作。取消继续等待原有清理完成后释放会话归属，不会提前允许第二条连接。
- 提示框与所属恢复任务一起关闭。旧提示框的延迟按钮／按键回调不能取消后续恢复；Activity 离开、启动后继窗口、失败、取消及完成都关闭原提示。
- API 的 `stream.feedback` 返回实际是否显示、标题、阶段及取消动作；按钮仍使用同一个动作分发器，没有额外控制协议。

## 验证

最终代码的 300 项单元测试全部通过，恢复类 25 项，包括清理期间实际取消、网络任务排队时阶段更新、旧按钮回调归属。Debug、本地 ARM64 Release 和测试 APK 构建通过。

在现有配对的无窗口模拟器 `emulator-5580` 上连接 winserver，临时使用 1920×1080、30 FPS、6 Mbps、软件解码及关闭声音。每条流程均执行一次真实串流、模拟终止后的正常底层清理／新 Activity／可见视频首帧，再执行第二次模拟终止并点击实际取消按钮。

| 流程 | 实际 Game 视口 | 初次首帧 | 恢复首帧 | 结果 |
| --- | --- | --- | --- | --- |
| 深色横屏 | 1512×1008，字体 1.0 | 2912 ms | 3302 ms | 恢复、提示、旧按钮无效、实际取消、清理及返回设备页通过 |
| 浅色窄屏大字体 | 960×540，字体 1.3 | 4477 ms | 4825 ms | 同上，取消按钮完整可见 |

第二条设置的模拟器尺寸为 540×960；Game 使用横屏，实际自身绘制尺寸为 960×540，不把它作为竖屏会话的验收。两条流程均为 JUnit `OK (1 test)`，共 22 张应用自身渲染图，其中视频图片只对应用自己的 SurfaceView 使用 PixelCopy。已查看两种主题的恢复提示，文本和按钮没有裁切。

证据：`D:\RHRemoteTools\ui-recovery-review-20261028`。`recovery-before-unit.xml` 保留修改前两项失败；`android40-unit-summary.json`、`recovery40-final-unit.xml`、两条 `native40-*.log` 和 `native40-*/session-real-recovery.json` 保留最终结果。正式 APK 为 `dist/android/RHRemote-v0.2.11-preview.40.apk`，版本码 264、仅 ARM64、非 Debuggable，沿用原签名。

## 边界

这是应用内明确标记的模拟终止，包含实际串流清理和恢复，不是物理断网或外网验收。两轮耗时是观察值，不能据此声称性能改善。临时 6 Mbps 沿用之前模拟器的排障条件，不替代默认 25 Mbps 的大帧调查、持续动态画面或 OPPO 实测。

未使用 computer use、系统截图或系统输入；未操作 OPPO、激活 Windows 预览、修改日常配置或重启服务。模拟器配置文件 SHA-256、本机偏好和服务器授权文件与测试前一致；尺寸 1512×1008、密度 240、字体 1.0 均恢复。Windows 保持 preview.47，Android 仅本地候选，未公开发布。其余 UI 流程及真实外网恢复继续保留在 TODO。
