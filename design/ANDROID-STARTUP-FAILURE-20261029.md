# Android 连接失败归属与恢复界面

错误归属修复为本地 Android `0.2.11-preview.79`，versionCode 297；后续 `preview.80 / 298` 补充原生拒收日志及正常会话复验。Windows 保持 preview.77，未发布。证据分别位于 `D:\RHRemoteTools\ui-connection-failure79-review-20261029` 和 `D:\RHRemoteTools\ui-rtsp-response80-review-20261029`。OPPO 未操作。

## 已确认的问题与改动

此前 portrait77-03 的客户端统计在 RTSP handshake 开始后记录媒体失败，而界面最终只保留 Desktop (409)。服务端随后出现约十秒初始 PING 超时。不能把这个等待直接当成编码耗时，也不能据此认定旋转导致了 409。

回放“RTSP 故障开始恢复 → 同一个旧启动控制器收到 Desktop / 409”可以确定复现一个代码缺陷：后到的冲突会被当成新的致命错误，覆盖错误提示并中止恢复。修改前定向回归 28 项中这一项失败，完整 XML 与日志保留。

现在只对已经开始恢复的旧控制器忽略该冲突。后继窗口有自己的控制器，其首次 409 仍然失败；401 等校验失败仍能停止恢复。没有改变证书、身份、重试次数或清理租约的规则。新增 JVM 回归还核对了取消后的旧回调与首次冲突，完整 JVM 回归 396 项通过。

错误提示保留具体阶段和错误码，例如“串流协商失败（RTSP handshake，错误码 -1）”；首次 409 提示本次连接与主机会话状态冲突。可恢复的首次失败现在也在清理前记录 name、portFlags 和 code，避免此前只有最终错误或泛化媒体失败的观测缺口。旧回调在有活动统计记录时单独记为 connection_stage_callback_ignored，不覆盖当前错误。

## 实际界面与恢复

使用专用 emulator-5580、既有配对身份连接 winserver，临时使用 H.264 / 1080p30 / 6 Mbps / 软件解码及无声。通过正常测试中断进入真实清理、地址解析和后继 Game 流程，再对旧控制器补入 409。它是受控回调复现，没有实际断开网络，不替代外网或真实 RTSP 错误的验收。

| 样本 | 原生结果 | 后继首帧信号 |
| --- | --- | --- |
| recovery01，浅色 | 旧 409 后恢复窗口保留，错误未覆盖，后继 Game 出现非黑解码画面 | 3844 ms |
| recovery02，深色 | 同上；再次恢复时旧取消回调被忽略，当前取消按钮可取消并完成清理 | 3946 ms |

两轮各导出了两个正常结束的统计文件，lost_events=0、size_limit_reached=false。recovery01 的旧统计中实际记录到 ignored 事件；recovery02 的界面和回调结果验证通过，但注入时没有对应活动记录，该事件未写入统计，不能宣称两个样本都有完整旧回调日志。

自身渲染图为 `recovery01/session-recovery-after-late-conflict.png` 与 `recovery02/session-recovery-after-late-conflict.png`。这些图来自应用对话框的 View.draw，没有使用系统截图或系统输入。

原生测试还补上首帧前失败时导出本次统计的收尾逻辑，不再只在取得首帧后把记录纳入导出列表。此次正向恢复验证不代替新增收尾分支的真实启动失败验收。

## 仍未完成的原因调查

portrait77-03 的原始 RTSP 失败及其 409 全部来源仍未确认。当前修复证明的是一个可复现的错误覆盖／恢复中止机制，不证明所有 409、初始 PING 超时或首次连接失败已经解决。该失败的客户端原始统计和服务端有界事件保留在上一轮 `portrait03` 目录。

### preview.80：已缩小到加密响应长度，尚未查明传输原因

继续读取模拟器保留的原生日志，确认两次真实启动失败均在 AES-GCM 解密前的完整性检查中被拒收：

| 原始样本 | 原生错误 | 请求 |
| --- | --- | --- |
| portrait77-03，1793222511.884 | Rejecting partial encrypted RTSP message，随后 request failed: -1 | ANNOUNCE |
| landscape78-06，1793223446.112 | 同一拒收错误，随后 request failed: -1 | SETUP streamid=video |

第二个样本随后自动重试成功，因此此前的正常最终统计不能证明第一次协商没有失败。筛选日志保留在新证据目录的 `historical-rtsp-errors.log`；没有保存响应正文、密钥或密文。这个错误证明客户端在读到 EOF 后，收到的总长度小于响应头声明的长度；它不证明是服务端发送、模拟器转发、客户端取消或头部内容中的哪一处导致。

对照当前服务端代码，TCP 响应已有循环发送全部数据的逻辑；客户端也循环接收直到 EOF。不能在缺少同次字节证据时把原因直接归为单次 send／recv，或改动重试与加密策略。`patch-android-rtsp-diagnostics.py` 只给现有三类加密响应拒收日志补充请求方法、声明长度、实际长度及 ConnectionInterrupted 状态，不记录请求正文或响应正文，不改变收发、解密、取消或重试。补丁在有序 Android 补丁末尾应用，重复应用的文件 SHA 一致，避免被前面的隧道补丁恢复掉。

原生会话测试还记录测试前已有的统计目录，收尾导出本轮所有新建且带 manifest 的统计，而非只取最后一个成功尝试。三轮正常样本各只有一份统计，均正常结束且 lost_events=0；这不代替多次失败后自动回退分支的实际验证。

| preview.80 样本 | 主题／附加范围 | 首帧信号 |
| --- | --- | --- |
| natural01 | 浅色，真实连接、分类控制、返回和退出 | 3967 ms |
| natural02 | 深色，同上 | 3835 ms |
| natural03 | 浅色，同上，加本地键盘路由、弹窗关闭和旧回调 | 3703 ms |

三轮均核对到非黑解码像素，主动退出后没有启动重连，临时配置、原备份和页面偏好恢复；日常 Windows 配置和主机授权文件 SHA 不变。natural03 的 Tab、Shift+Tab、方向键、Enter、Escape 等经应用内 KeyEvent 分发；正向边界对照可到达远端翻译器，随后本地面板路径的远端翻译调用为 0。不是实际外接键盘或物理系统输入验收。

本轮没有复现响应不完整，新增长度字段尚无自然失败值，不能声称已修复该原始错误。测试条件仍为专用模拟器、局域网、1080p30／6 Mbps／软件解码／无声。Windows 只枚举到无物理名称的 DISPLAY26 虚拟屏，没有向主屏或虚拟屏启动新预览。

模拟器、受控回调、软件解码和较低测试码率，不代替 OPPO、实际外网变化、默认码率、长期稳定性、物理显示呈现或完整 UI 目标完成。
