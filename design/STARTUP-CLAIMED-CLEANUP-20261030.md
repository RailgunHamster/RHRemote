# 启动失败后的会话占用与恢复

本地 preview.108 修正了 Android 与 Windows 客户端对启动清理回执的解释。Windows 日常客户端仍为用户批准安装的 preview.101；后续候选没有替换日常安装，没有操作 OPPO。

证据目录：`D:\RHRemoteTools\ui-android-conflict108-review-20261030`。

## 已定位的错误链

必须一起分析同一次测试导出的所有统计文件。`20261030-insets107-dark08` 的 `session-recovery-metadata-1.jsonl` 才是首次失败，`metadata-0` 是后继请求：首次 RTSP 握手失败（-1），没有客户端 `connectionStarted`，但清理等待仅约 51 ms 就结束；约 2.70 秒后，后继 Desktop 请求收到 409。只读最后一份记录会漏掉首次 RTSP 失败。

主机返回的具体原因是已有启动请求或串流，不能在该时刻选择初始屏幕。服务端代码显示 ANNOUNCE 阶段已占用启动槽并分配串流，控制通道尚未建立；这时取消接口仍返回 `handed_off`。旧客户端将此回执当作真正连接完成，过早发起下一次启动。服务端日志中原串流随后才出现约 10 秒的 Initial Ping Timeout。因此这几次 409 是前一次失败尚未清理完的后续结果，不能一概视为其他用户正在连接。

`serverinfo` 的 BUSY 只由当前 app ID 决定，不是活动串流数量的证明。没有据此全局结束主机应用、停止服务或清理其他客户端。

## 客户端改动

协议中的 `handed_off` 在客户端解析为非终态 `claimed`。只有本客户端真实的原生启动成功回调才确认 handoff；握手失败时，继续用同一请求的凭据查询清理，收到 cancelled、finished 或 expired 才允许后继启动。请求凭据不进入持久配置、同步、UI 或统计。

默认服务端启动 PING 超时约 10 秒；客户端的有限清理预算改为 15 秒，给一次轮询、有限 HTTPS 请求和调度留出余量。Android 等待回调预算为 17 秒；Windows 外层进程清理预算为 20 秒，避免外层先结束内部 15 秒任务。正常连接不经过这段等待；预算用尽也不伪造清理成功。非默认的更长服务端超时仍可能导致清理超时，需要继续保留失败状态。

Android 对已知 409 原因给出中文说明，不展示服务器返回的任意文本；最初失败仍保留在最终错误中。旧会话的迟到错误不得覆盖后继会话，成功首帧清除此前的失败原因。恢复期间保留可见、可用的取消入口。

## 验证与边界

- Android 完整 JVM 回归 426 项通过；Windows 原生回归覆盖 claimed 后过期、同一凭据重试、真实 handoff 与在途回执竞争、无确认时有限退出。
- `20261030-conflict108-dark01`、`light02` 在真实 winserver 会话中通过各六组横竖屏系统边距验证，补齐 preview.107 缺少的深色实测；这两次没有触发启动恢复，不能据此认定恢复分支通过。
- 首次受控启动中断 `20261030-conflict108-claimed03` 真实进入 claimed 分支，但原 10 秒清理预算到期，整轮保留失败；恢复对话框的取消按钮可见且启用。此失败推动清理预算调整，不能计作恢复通过。
- 调整后的 `20261030-conflict108-claimed05` 完整原生流程通过：旧请求收到九次 claimed 后收到 expired，实际清理等待 **10.187 秒**，后继串流成功启动，没有后继 409 或清理超时。总计约 **19.359 秒**包含主动制造的失败、清理与重新连接，不是正常首帧耗时。等待时取消入口可见且启用，后继会话完成六组系统边距检查并正常退出。
- `claimed05` 首次外部配置核对因 SharedPreferences XML 元素顺序变化而失败；逐项比较证实值相同，进程退出后用测试前的完整私有备份恢复，14 份文件逐字节一致。保留初次差异和最终核对，未通过修改产品设置来迎合测试。
- 中间的 `claimed04` 是测试准备错误：将 ARM64 包用于 x86_64 模拟器，触发 ARM 转译层 `kHasAES` 检查，未进入目标恢复分支。已换回原生 x86_64 测试包，13 份配置已恢复；当时测试只将全局偏好保存在进程内，旧更新时间没有落盘，不能宣称该次崩溃前后的全局偏好文件也逐字节恢复。后续用例已增加全量私有文件备份。此限制只涉及专用模拟器，不涉及日常 Windows 配置或 OPPO。
- 受控故障只在专用模拟器的测试 APK 中注入一次原生启动中断，没有实际断网、没有远程输入；它不等同于自然 RTSP 缺字节或外网断线。
- Windows 物理副屏当前未活动，候选仅完成后台构建和原生回归，没有用虚拟屏代替物理窗口验收。

自然故障的 RTSP 响应曾记录预期 52 字节、实际 51 字节，涉及 ANNOUNCE／PLAY。缺失字节的最初来源仍未确定；本次不宣称解决它，也没有放宽协议长度、加密或证书检查。其他主机、真实外网、OPPO、公开发布与整套 UI 验收继续保留。
