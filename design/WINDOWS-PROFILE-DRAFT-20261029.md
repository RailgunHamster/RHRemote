# Windows 连接设置的草稿归属

Windows 本地候选 `0.2.11-preview.88`，Android 保持 preview.87。本轮修复快速切换设备后，旧控件命令误作用于新草稿的问题；未修改串流、服务端或 Android 生产代码。证据目录：`D:\RHRemoteTools\ui-profile-origin88-review-20261029`。

## 已复现的用户影响

使用生产 Slint `MainWindow`、状态绑定和实际按钮回调，在真实控制器与独立本地配置文件上复现了三个失败：

- winserver 设置中的“增加帧率”已入队，但执行前选中了 Claw，旧命令修改了 Claw 草稿。
- 旧页面的“保存”已入队，切换／重开后，它提交了后来打开的设备草稿。
- 旧“取消”已入队，即使后来重开的是同一设备，也会丢掉那次新草稿。

修改前 `before88.log` 中三项均失败，返回 `ok:true`，而非正确拒绝。测试没有接触远程主机、系统安装器或 WebDAV。

## 最终行为

每次新开连接设置生成独立的 `profileDraftId`。再次选择当前已打开设备、普通输入和分类切换保持该编号；关闭／保存使它失效；将来源配置复制到草稿后更换编号。

Slint 按钮及输入回调在入队时携带当时渲染的编号。后端先核对它，并在实际修改草稿的同一个状态锁内再次核对，覆盖入队后和接收后发生的切换。保存并继续的内部保存也携带该草稿编号，避免确认与保存之间替换草稿后误提交。

过期操作返回 `ok:false, ignored:true, reason:stale_profile_draft`，不修改当前输入、错误提示或配置文件；主窗口队列不会把它作为新页面的失败提示。当前草稿的操作继续正常执行。省略 `draftId` 的即时 API 保留既有语义，不要求旧调用方先升级。编号仅用于本次运行的动作归属，不是凭据，不进入配置同步文件。
