# Android 主动设备检查与状态归属

2026-10-31，本地候选 **0.2.11-preview.152 / 370**。沿用已选设备工作区和原生 Java View，补齐主动检查的线路策略、身份来源及状态反馈。本轮未操作 OPPO，未发布或覆盖日常客户端。

## 用户流程

未确认设备的主按钮“检查连接”现在调用共享动作 **device.check**，立即进入可取消任务。任务使用该设备已保存的地址、启用线路及顺序、网络模式、中继地址和本机固定证书；列表“刷新”及原 devices.refresh(uuid) 仍是普通发现刷新，不在后台打开媒体中继。已配对或已有检查结果的设备，在设备信息下也可重新“检查连接”。

任务使用独立执行队列，复用现有诊断的前台通道归属及取消／清理机制。上方显示设备名称与“取消检查”，跨页保留；清理失败时保留占用并提供“重试清理”，完成清理后才发布结果。没有自动配对、开始串流或写入共享配置。

按钮参数冻结本次设备及网络配置；配置或固定证书变化后，旧结果不再决定按钮。后台发现的新观察也不能被一次旧成功检查永久盖成在线。普通发现未覆盖完整线路时，不能把它的一次失败当作所有线路都离线：可达状态改为待确认，已保存的配对继续保留。API 的 reachabilityStatus 与配对结果分别表达这两类事实。

| 主动检查结果 | 主操作 |
| --- | --- |
| HTTP UUID 匹配，无本机证书 | 配对；HTTP 的 PairStatus=1 也不当成已认证配对 |
| 固定证书 HTTPS 已配对 | 连接 |
| 固定证书 HTTPS 未配对／401 | 重新配对 |
| 对端证书与固定证书不同 | 重新配对，并提示确认目标 |
| TLS 失败／超时／不可达，但本机有证书 | 保留连接入口；实际准入继续严格校验 |
| UUID 不符或设备信息无效 | 检查连接；显式连接和配对也被拒绝 |

无证书且状态仍未确认时，保留明确配对入口。所有按钮仍经动作 API，不依赖系统输入或 computer use。

## 协议与连接准备

新增的 NvHTTP 只读方法使用原 HTTP／TLS 实现，响应体上限 64 KiB，每次请求有调用预算。固定证书检查使用原严格校验；用具体证书异常区分证书不符和其他 TLS 失败。HTTPS 的 HTTP 401 与 XML 401 都归为认证拒绝；未取得 HTTPS 证据的 HTTP 401 不推断为配对被拒绝。失败后不降级到 HTTP 来认证配对。

选路预检已读取的 UUID 匹配响应只在本次任务内传递，不放进共享配置或公开选路报告。无证书检查实测 **1 次 HTTP、0 次 HTTPS**；有证书检查实测 **1 次 HTTP、1 次 HTTPS**，从预检响应取得 HTTPS 端口，避免重复 HTTP 查询。普通连接路径不启用这份响应捕获，保留原调用入口。

检查得到的已认证配对状态用于连接准备副本，避免旧发现标志把“连接”转进配对；未知认证状态则要求重新严格查询。显式重新配对的准备另走 UUID 校验的 HTTP，只取得设备信息，保留原固定证书；实际 PIN／证书替换仍交给原配对流程。成功配对或真正首帧会使旧检查记录失效，不改原始设备对象来换取成功。
