# Android 会话悬浮控件的动态安全边距

Android 本地 preview.107 修复了实际会话中系统栏出现后，悬浮键盘及顶部控制开关不重新避让的问题。Windows 日常仍为 preview.101；没有操作 OPPO，没有更改传输、编码或远程输入逻辑。完整 UI 目标仍未完成。

证据目录：`D:\RHRemoteTools\ui-android-insets107-review-20261029`，测试跨越 10 月 29／30 日。

## 真实故障及原因

preview.102 的 `20261029-insets102-baseline04` 在真实 winserver 串流中复现。显示系统栏前后，Game 的内容窗口均为 1512×1008，系统安全边距从全零变为上 36、下 48 像素；Esc 仍在 y=24，顶部控制开关仍在 y=12，分别没有达到新的 y=60、y=48 安全位置。方向键也没有避开底部导航区域。`baseline-bug-verification.json` 和原始会话样本保存这些数值，整轮记录为失败。

原代码只在父 View 布局变化或控制状态刷新时重新读取边距。全屏窗口的系统栏变化不会必然改变内容尺寸，所以原来的尺寸监听不能覆盖该路径。Android 官方对全屏 View 的建议同样要求处理系统栏及显示缺口的 insets。[官方说明](https://developer.android.com/develop/ui/views/layout/edge-to-edge)

现在在本应用自己的悬浮键盘层和始终存在的控制开关上监听 insets，收到边距后立即重排。原父级监听不替换、原 insets 不消耗，其他视频／触控 View 继续收到事件；销毁时移除自己的监听。原尺寸监听保留，关闭按键和面板互斥、共享动作及开关样式不变。

## 当前有效验证

- Android JVM 418 项通过，无失败、错误或跳过。新增两项检查在父尺寸不变时更新位置、事件继续传递、父监听保留、销毁后不影响父监听，且不发出远端动作。
- `20261030-insets107-light06` 在真实 Game、同一连接和同一统计记录内，完成横／竖屏各三次“隐藏 → 显示 → 再隐藏”边距检查，共六组、每组十个悬浮键。按键不重叠，控制开关避开系统栏，系统栏隐藏后回到原位置。
- 横屏显示系统栏时，Esc 从 y=24 移到 60，控制开关从 y=12 移到 48；隐藏后分别回到 24、12。内容尺寸保持 1512×1008。
- 横竖屏由专用模拟器实际显示模式切换，Game 没有重建，统计会话没有更换；这不是物理传感器或 OPPO 转向验收。各步使用自身解码 Surface 的 PixelCopy 加 View.draw 合成，不截取系统屏幕。
- 会话后显示尺寸恢复为原 1512×1008、240 dpi；设备、身份、WebDAV、偏好及数据库共 14 份文件与该次测试前逐字节一致。数据库只在自有 Activity 已退出、目标进程不存在后恢复。没有停止业务服务或发送远端按键，声音保持关闭、主机声音保留。

深色主题的 `20261030-insets107-dark07`、`dark08` 均在 Desktop 阶段收到 409，未进入安全边距验证，不能算作深色真实会话通过。后续本地 preview.108 的 `20261030-conflict108-dark01`、`light02` 已分别完成六组真实 Game 横竖屏安全边距检查，每次恢复 14 份配置并正常退出，补齐深色范围。旧失败保留，具体启动占用链见[后续定位](STARTUP-CLAIMED-CLEANUP-20261030.md)；这两轮正常连接不代表失败恢复分支通过。

## 保留的失败与测量修正

- `baseline01` 和 `baseline03` 的测试误把原生 Switch 的 `performClick()` 返回值当作状态变化成功的条件；第三轮的完整控件元数据证明开关可见、可用，实际回调已经改变状态。已改为检查 checked 和实际会话状态，没有为此改产品点击逻辑。[CompoundButton 实现](https://android.googlesource.com/platform/frameworks/base/+/c80ad99a33ee49d0bac994c1749ff24d243c3862/core/java/android/widget/CompoundButton.java)
- `baseline02`、`20261030-insets107-dark07`、`dark08` 在 Desktop 阶段收到 409，尚未进入本次安全边距验证。原始元数据与清理记录保留；409 的具体服务端原因仍待定位。`serverinfo` 的 BUSY 由当前 app ID 决定，不能单凭这个字段认定有活动串流，更没有据此全局结束主机应用或其他客户端。
- `20261030-insets107-light05` 已通过横屏的新边距断言，但测试临时强制 Activity 方向与 Game 的 FULL_USER 规则冲突，竖屏阶段回到横屏，整轮保留失败。后续改用模拟器实际显示模式并在 finally 中恢复，没有改产品的旋转策略来迎合测试。
- 最初一轮正常设备发现改写了模拟器数据库缓存，其他 13 份配置／身份文件不变。不能宣称整个测试过程从最初开始 14 份文件完全没有变化；后续正式用例各自保存数据库，并在进程退出后恢复，逐次核对 14 份文件。

连接配置经应用共享设置动作临时设为 1080p30、6 Mbps、软件解码、无声，结束后恢复。UI 短测及图像中出现的慢连接提示不替代稳定帧率、丢包、默认码率或外网验收。物理缺口、多窗口、全部方向、OPPO 及发布／真实更新流程继续保留在 TODO。
