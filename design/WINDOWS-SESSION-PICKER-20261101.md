# Windows 菜单点击归属与长列表键盘

2026-11-01，本地 UI 源码／软件控件测试版本 `0.2.11-preview.187`。修复菜单行在鼠标按住期间目标变化，或短暂不可用后恢复，仍执行旧按压的问题。日常客户端未替换，本轮未生成正常安装包或公开发布。

## 已复现的问题

旧菜单行在松开时直接读取 `root.values[index]`，没有记录按下时的目标。受控地保留该行并将编号从 `display-a` 改成 `display-b` 后，真实控件回调、Controller 参数转换及测试适配器均收到 `display-b`。这不是仅比较界面字符串，也没有向真实主机发送切屏请求。

另两类场景是在按住期间让菜单变为忙碌，或禁用该行，然后恢复可用。旧控件恢复后仍会执行这次旧按压。三类变化 × 两种尺寸 × 两个主题，共 12 组不符合预期。

本轮将仅更新目标编号与完整生产方式的列表重建分开检查。旧版完整重建和切换菜单种类的八组场景原本已取消点击，保持这一行为；不能将本轮结论扩大成所有后台列表刷新都会误选。

## 修改后的行为

- 按下时记录菜单种类与目标编号。
- 目标编号或菜单种类变化，或控件在按住期间变为不可用，取消这次点击。
- 普通点击、其他行更新，以及同一目标仅改名，仍发送原目标一次。
- 键盘和无障碍激活继续采用当前目标；现有 `stream.display.select`、`stream.shortcut` 等动作 ID 和参数不变。

列表行采用与普通按钮一致的按下归属检查，按目标编号识别，名称变化保持可点击。本次生产修改限于该列表行的指针处理及 UI 版本标记，没有修改连接或输入协议。
