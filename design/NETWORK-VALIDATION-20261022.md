- Windows 经 winserver 的 Tailscale IPv4 地址收到串流首帧，实际配置为 H.264 / 1080p30 / 25 Mbps / 静音，VPN 分包 1024 字节。首帧 CPU 提交约 2398 ms；不将它解释为物理呈现时间或稳定帧率验收。
- 一次性诊断使用不可达的局域网首选地址与有效 Tailscale 备用地址：首选返回不可达，备用约 5 ms 匹配主机 UUID；未修改原保存地址。
- winserver 的配对鉴权接口与 UDP 单次票据探测通过；TCP 四个必要端口可达。主机端匿名连接不能获得网络接口权限。
- winserver / claw 的统一服务升级成功，安装器确认 UUID 保留，新增规则限制 Tailscale 网卡和地址范围。本机服务更新已准备 UAC 方案，尚待确认。
- Android APK 和 JVM 测试通过；没有操作 OPPO。Windows / Android 的地址和网络参数参与已有 WebDAV 配置模型。

## 公网 DERP

用户指定 SSH 别名 `tc`。该服务器已运行 DERP，现有 tailnet 下发对应中继区域。未改动现有 Tailscale / DERP 配置，也未触碰其他业务服务。

使用官方 Tailscale DERP 客户端库创建两个临时身份，经公网 HTTPS 连接该中继，双向传输有序的合成诊断数据；不读取原节点密钥，不采集画面或声音。测试通过从 SSH 获取的公开证书进行证书哈希校验，不使用关闭校验来冒充 TLS 验证通过。

| 连续发送目标 | 每方向数据 | 正向有效速率 / 丢包 | 反向有效速率 / 丢包 | RTT |
| --- | --- | --- | --- | --- |
| 5 Mbps | 1 MiB | 4.93 Mbps / 0% | 4.93 Mbps / 0% | 51–56 ms |
| 25 Mbps | 1 MiB | 11.51 Mbps / 1.17% | 8.52 Mbps / 25.39% | 56–58 ms |

这些结果证明实际中继可用，同时说明本轮路径不能稳定承载 25 Mbps。单次短测不能确认瓶颈完全属于云服务器带宽，仍需区分公网路径、带宽限制与 DERP 队列。外网码率上限可独立设置，不改变局域网画质配置。

不带限速的突发传输曾出现队列丢包，因此没有用突发结果宣称“数据损坏”或中继完全不可用。通用 `tailscale debug derp` 对该自签名证书报错，与主传输库处理自定义节点配置的方式不同，不能单凭该报错判定 Tailscale 中继失效。
