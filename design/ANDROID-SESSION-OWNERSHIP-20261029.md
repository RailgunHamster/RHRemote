# Android 旧会话控件的归属

本地 Android `0.2.11-preview.82 / 300`，Windows 保持 preview.81。未发布。证据目录：`D:\RHRemoteTools\ui-session-owner82-review-20261029`，OPPO 未操作。

## 已复现的问题

会话控制面板的普通按钮、滚动开关和音量滑块直接调用共享动作分发器。面板从窗口移除后仍保留监听器；恢复创建新控制器后，旧控制器的控件也可能尚未销毁。共享分发器此时指向新会话，旧回调会操作新目标。

| 修改前复现 | 实际结果 | 证据 |
| --- | --- | --- |
| 已销毁面板保留按钮引用及一次未结束的音量拖动，建立新面板后触发旧回调 | 发出断开、输入模式、滚动模式及两次音量动作 | `before-RhStreamPanelTest.xml` |
| 尚未销毁的旧控制器仍有按钮，将共享分发目标替换为新目标后点击旧按钮 | 新目标收到 stream.mode.toggle | `before-RhSessionMenuTest.xml` |

两个修改前定向回归均失败，日志为 `before82.log`。这证明可复现的回调归属缺陷，不声称已经在用户的物理设备上观察到每一种延迟回调。

## 改动

控制面板统一通过销毁检查发送动作，销毁时清除本地拖动状态；旧音量拖动完成和无障碍进度回调不再提交。实际会话中的面板、悬浮键盘、对话框和返回动作，还要核对控制器仍是当前会话的动作目标。旧 Game 的键盘手势也使用同一归属检查。

正常控件通过检查后继续调用原来的 RhActions.click，没有另建操作协议或改写 API 的当前会话语义。销毁检查解决已经退役的 View；控制器归属检查解决尚未销毁、但已被新会话替代的窗口。未改动视频、网络、服务端、重试策略及用户持久参数。

## 验证范围

完整 Android JVM 回归 399 项通过。新增两项同时检查旧控件被拒绝、新面板或当前动作分发仍能正常工作，避免将所有动作屏蔽后误判为通过。

专用模拟器使用既有身份真实连接 winserver，临时 1080p30／6 Mbps／软件解码／无声。native01 首帧信号 3276 ms；通过受控中断执行实际清理和后继 Game 创建，恢复首帧信号 3369 ms，两次均取得非黑解码像素。没有实际断开网络。

原生流程保留旧窗口真实 View，后继窗口出画面后分别调用旧“断开”、输入模式、滚动开关、悬浮键盘开关和控制开关，并调用旧 Game 的键盘手势；新会话的连接、输入模式、键盘、声音、面板和对话框状态均不变。新窗口中完整可见的输入模式按钮可切换并恢复。此时旧控制器已销毁，记录为 `session-retired-controls.json`；尚未销毁的替代边界由 JVM 回归证明，不混称为同一个原生样本。

本轮还验证了正常软键盘打开、返回与手势收起、取消尚未完成的键盘请求、弹窗返回、旧对话框回调以及新会话正常退出。两个统计文件均正常 trace_end，lost_events=0、size_limit_reached=false。没有发送远端文本、快捷键或 Ctrl+Alt+Delete；按键及点击通过应用自身回调执行，没有注入操作系统输入。

模拟器共享配置、偏好和原备份已恢复。该结果不替代 OPPO、真实外接键盘、外网断线、默认码率长期运行、Windows 实体悬浮窗或整个 UI 目标的验收。
