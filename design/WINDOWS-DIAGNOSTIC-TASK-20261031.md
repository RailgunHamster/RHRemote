# Windows 连接诊断任务与页面反馈

本地候选 preview.150，Android 保持 preview.149。本轮不覆盖 Windows 日常 preview.101 或模拟器正常 Android preview.129，不操作 OPPO，不发布或启动远程串流。

原“诊断连接”直接占用普通操作队列，既无忙碌状态和取消，也会让后续导航等待网络结束。`queue-red.log` 用真实生产队列暂停诊断：发出打开设置后 500 ms 仍停在设备页；相同检查在新任务实现下通过。这个等待与远程首帧耗时无关。

现在 Controller 先固定设备、地址及客户端配置，再异步运行独立任务，普通队列立即继续。设备网络页显示忙碌、取消、清理、完成／失败及详情开关；离开网络页后，固定任务条保留设备名称和取消／重试清理。另一台设备保留自己的操作名称，不冒充当前任务设备。错误不再在其他页面留下第二份全局提示。

## 操作归属

实际开始按钮带目标 UUID、设置页 draftId、expectedIntent 和 expectedOperationId；取消绑定 operationId／expectedAction，详情绑定 UUID／operationId／expectedExpanded。按住按钮期间切换设置或任务后，旧事件不能转成新操作。API 省略页面上下文时仍允许对指定已保存设备发起诊断；界面始终携带完整上下文。

诊断与配对、连接及恢复互斥，更新安装同样等待任务结束。取消立即设置标记，清理完成前仍 busy；失败保留任务和资源归属，“重试清理”只执行 cleanup，不重复网络诊断。关窗先经过原有未保存保护，再取消诊断并等待清理，最后调用既有关闭路径。

完成结果不改当前草稿、搜索、选择、焦点或其他页面提示。结果在按钮上方显示，详细记录展开后仍由固定分类／保存栏包围。只在原操作仍有焦点、结果行位于当前可见操作附近时，补显被裁住的标题；普通刷新、编辑器焦点和滚动到其他区域不触发拉回。

## 原生资源与边界

Native 的任务构造不运行网络，工作线程才申请可取消的前台租约。旧列表检查先取消并完成清理，当前诊断才能使用同一通道；等待期间取消不会释放旧检查的租约。工作线程重新核对会话、恢复、配对及未结束的清理，拒绝介入原有连接。

主机辅助检查仍通过原配对身份和原生固定证书验证，只读取诊断接口。每次使用随机命名的私有请求／响应文件，并记录本次创建成功的路径；清理仅处理这些文件和本次子进程，不使用旧的固定文件名。取消主机检查会结束并回收本次子进程，其他串流子进程保留。通道及探测线程清理完成后才释放租约；清理失败保留任务供显式重试。

诊断使用单独的有界 HTTP／DNS 路径，并等待本次探测线程结束。正文读取保留 1100 ms 预算，TCP 每次建连 500 ms，主机辅助子进程最多 12 秒且每 25 ms 检查取消。已有传输工作进程的有界退出仍可等待至 25 秒；这段时间会显示取消／清理，不能提前当作已经释放。普通连接的选路、证书、解码和首帧逻辑不在本轮改动范围。
