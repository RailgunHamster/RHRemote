# 副屏预览与 UIA 检查

Windows 本地预览为 0.2.11-preview.42，未发布。Android 未改动，OPPO 未操作。

用户要求测试使用副屏，并明确指出不应依靠 computer use。后续业务操作、控件事件、日志和自身渲染图均走应用接口；不自动恢复需要激活窗口的原生焦点测试。此前通过接口反复激活窗口也造成了干扰，不能以“没有调用 computer use”作为理由继续。

## 当前安排

- `Start-RHRemoteUiPreview.ps1` 通过只读 QueryDisplayConfig 确定实体副屏的物理坐标，默认目标为 `\\.\DISPLAY2`。本机对应左侧 C3273IUY、3840×2160，桌面位置为 (-3840,0)。主屏、未连接或无名称的虚拟屏均不能成为此启动器的默认回退。
- 程序在显示主窗口前配置物理位置，保持不激活。隔离预览缺少显示器和位置参数时拒绝启动；日常客户端启动不受影响。后续预览必须使用此启动器，不能重用历史 QA 启动脚本直接开到主屏。
- preview.42 实际启动后，接口核对 `monitor=\\.\DISPLAY2`、位置 (-3776,64)、`windowActive=false`。自身截图为 2655×1755，包含原有三台设备；未截取桌面或其他应用。
- `Test-RHRemoteUiAutomation.ps1` 默认拒绝激活式测试。仅显式允许时才激活一次，后续失去激活便停止，不反复抢回焦点。用户工作期间不启用此开关，只做接口和只读检查。

## 已发现和修复

- UIA 只有在窗口真实激活时才上报控件焦点；未激活时没有焦点与应用内部的焦点记录并不矛盾。已核对的刷新、侧栏和连接设置按钮能跟随 UIA 焦点；失去激活的记录不算通过。
- 搜索框的测试标签原先存在，但实际无障碍输入控件没有名称。回归先失败，补上标签后通过；preview.41 实际 UIA 记录确认名称为“搜索名称或地址”。自定义按钮、侧栏、设备行及标准输入／选择控件也提供与应用接口相同的标识，减少同名控件歧义。
- 按进程取得的 `MainWindowHandle` 曾指向空标题、无控件的窗口，不能作为正确主界面的证据。现在从控件接口取得确切 `nativeWindowHandle`，再校验所属进程。显式测试激活还等待窗口恢复和布局就绪，之后才聚焦。
- 最终核心 107／UI 123 项测试通过，共 230 项。新检查包含缺少副屏参数不会显示隔离预览，日常启动不受影响。激活式验收的默认拒绝也已实际核对。
