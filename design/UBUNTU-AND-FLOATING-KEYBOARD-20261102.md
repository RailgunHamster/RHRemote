## 修复与检查

- 服务端广播上下文清理仅退休已认领的旧启动槽，保留新的 HTTP 准备与未认领 RTSP 请求，避免误发 410。显式关闭与撤销仍取消请求。
- 客户端恢复已出画面的会话时优先原路径；409 / 410 的暂时繁忙单独计数，不消耗三次媒体重试，仍受 60 秒上限约束。同一原生进程的状态只处理一次。
- Linux 使用 XDG 客户端目录、原生 Secret Service、pidfd 父进程守护、X11 原生窗口身份与输入区域。绝对指针通过 X11 完成定位，其他键鼠输入继续使用 uinput。
- Windows 界面测试 329 项通过；最新恢复策略 8 项专项通过。Android 681 项通过。Linux core 183 项、host 13 项、X11 归属／位置 2 项及恢复策略 8 项通过。原生父进程与启动注册表回归通过，构建使用的 8 个 Sunshine 修改文件与提交来源一致。
- Linux 全量界面首次为 266 项通过、2 项失败、8 项忽略；两项失败分别由未解锁密钥环的 SSH 环境与测试门闩的 5 秒限制引起，已在独立密钥环及修正测试同步后专项通过。测试同步修正不改变产品超时。

## 保留边界

Ubuntu 20.04、Wayland、ARM、实体 GPU 性能、Linux 外网与长时间动态呈现尚未验收。独立 Xorg 桌面只支持没有其他图形会话的服务器；初始 1920×1080，不自动生成任意平板显示模式。Ubuntu 更新使用 `.deb` 手动覆盖安装。

曾有一次 X11 测试窗口只记到“向上”的松开事件，当时未同步采集内核事件，原因未确定。后续同步采样的 100 次按键全部完整，不能据此宣称该单次样本已修复；原始样本保留并继续列入 TODO。
