# Windows 悬浮键盘：字体修复与副屏回执

Windows 本地候选 preview.89，Android 保持 preview.87。生产改动仅将 Windows 键帽 `⌫`、`⇧ Tab` 改为 `Backspace`、`Shift+Tab`，保留按键编码、位置、点击区、透明度和默认关闭规则。未发布，未操作 OPPO。

证据根目录：`D:\RHRemoteTools\ui-windows-floating89-review-20261029`。使用实体副屏 `\\.\DISPLAY2` / C3273IUY，当前缩放 **225%**，远程源为 winserver 原有物理主屏，串流请求 1920×1080、30 FPS、25 Mbps、声音关闭；没有调整源屏分辨率或布局。FPS 是请求值，本轮没有验收动态帧率。

## 字体问题与对照

preview.88 的实际悬浮窗口导出中，退格键只有空白键帽，Shift+Tab 只显示 Tab。界面和无障碍标签存在，远端也收到正确按键，但用户无法从键帽辨认功能。当前软件绘制字体没有显示这两个特殊符号；改用普通文字后，浅深主题均完整显示。

自身窗口导出的 `keyboard-visible.png` 是 Slint 绘制结果，不是系统桌面截图。PNG 不包含 Windows 后续施加的整体窗口透明度；透明度 **166** 另由运行时 `GetLayeredWindowAttributes` 读回核对。

`legend-pixels-final.json` 排除边框后核对键帽内部文字像素：

| 键帽 | 修改前浅色 | 修改后浅色 | 修改后深色 |
| --- | ---: | ---: | ---: |
| Backspace | 0 | 933 | 849 |
| Shift+Tab | 326（仅 Tab） | 787 | 698 |

新文字的像素边界均完整位于按键内部。浅色文件为 `after-light01/keyboard-visible.png`，深色为 `after-dark03/keyboard-visible.png`；完整窗口图也已人工查看。

## 实际输入和点击区域

使用独立测试身份、原生 Slint 按钮及应用 API，连接后只向经 PID、运行编号、前台及落点核对的临时 WinForms 窗口发送输入。客户端没有系统输入注入或 computer use，没有发送安全注意序列、改动剪贴板或测试其他用户窗口。

- preview.88 基线完整通过：10 个悬浮键各一次回执，18 次实际控件派发，开关、隐藏和正常断开通过。
- preview.89 浅色 `after-light01` 完整通过同一流程：Tab、Shift+Tab、四个方向、Enter、Backspace、Delete、Esc 各收到一次，每次修饰键残留为 0。
- preview.89 深色 `after-dark03` 的同样 10 个键也都有回执，字体、区域及透明度通过；后续会话及退出未通过，见下一节，不能将它记作完整通过。

实际区域读回确认全部键中心属于窗口，中央和远离按键的角落不属于窗口。方向键位于右下倒 T，Tab 位于左侧偏上。面板展开后键盘隐藏，浅色随后通过实际开关关闭。几何和读回保存在各轮 `keyboard-native-shape.json`，逐键远端记录为 `probe-*.json`。
