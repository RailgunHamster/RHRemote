# 已显示会话的首帧状态回退

后续 preview.93 发现并修复本轮回退记录未更新声音成功回执的缺口：旧值可能覆盖刚设置的音量／开关。preview.92 的下述按键与首帧结果保留，不能据此认定声音控制通过；当前候选及明确区分的复验范围见[声音回执修正](WINDOWS-AUDIO-ACK-20261029.md)。

Windows `0.2.11-preview.92` 修复同次会话已确认首帧后，原生状态接口短暂不可用、回读早期状态文件时重新显示“等待主机首帧”，甚至触发初始首帧超时断开的问题。同时修复首帧超时分支没有核对实时 HTTP PID 就发断开的缺口。

这不等于解决[preview.90 中 UI 从未确认首帧的 577 帧失败样本](WINDOWS-NATIVE-CONTROL-20261029.md)。本轮针对已确认首帧之后的状态回退；原生接口长期不可达、初次状态丢失和 15 秒退出超时仍需定位。[此前分段采集](WINDOWS-NATIVE-STATE-20261029.md)继续保留。

## 复现与修正

新增回归使用真实 localhost HTTP 服务及有独立句柄的测试子进程：先报告当前 PID 已出首帧，再返回 HTTP 503，回退到该 PID 的 `connected / streaming:true / firstFrame:false` 文件。测试把起点移动到已连接 31 秒，验证超时决策，不把它算作 31 秒实测。旧代码向测试服务发送了一次错误的首帧超时断开。

第二个回归让 HTTP 服务报告不同 PID，旧代码仍发送断开。服务只计数，不断开任何应用。行为基线为 **5 通过、2 失败**，原日志保留。更早一次测试夹具将 `Arc<Controller>` 写成 `Controller` 导致编译失败，该次没有运行用例，也不计作行为复现。

修正保持同次进程的已确认首帧记录，并只保留窗口句柄、声音开关和音量这些有限字段。读取失败且回退文件仍属于该存活进程、仍报告已连接、没有真实错误时，恢复已确认的首帧及文件缺失的这些字段；窗口使用前仍由现有代码核对 HWND 的 PID。不会复制整个旧状态，也不会覆盖错误、断流或释放标记。

新原生进程交接时清空记录；即使 PID 相同的新交接也不继承。实时接口明确重置首帧，或同进程报告真实中断／错误时，旧记录失效。从未确认过首帧、不同 PID 的文件均不能产生成功状态。已确认首帧的当前进程也不会再次消耗初次首帧等待预算。

派生状态使用 `firstFrameFromMilestone:true` 标记；`statistics.nativeControl.firstFrame` 仍保留本次原始文件中的 false，`native_first_frame_restored` 记录恢复使用。没有改写原生文件来伪装它已经记录首帧。

首帧超时只有在本次实时 HTTP 响应 PID 与当前存活子进程一致时才发送断开。缺少这个核验时不向该接口发命令；原来针对实际持有子进程的有界退出路径没有改成操作其他 PID。该检查不宣称跨请求的原子身份绑定，也没有放宽原有初始等待上限。

## 回归与隔离测试接口

最终核心 **129**、Windows UI **204** 项通过，另有 **1** 项既有 UIA 用例忽略。新增边界覆盖旧文件、未见首帧、进程替换、同 PID 新交接、不同 PID 文件、真实中断、实时首帧重置、错误 HTTP PID，以及正常客户端禁止启用模拟故障。

为实测界面，增加测试专用 `view.ui.native-state-fault {processId,polls}`。它只在既有隔离预览条件成立时启用，并要求本次存活、已确认首帧的原生 PID；每批 1～8 次父客户端状态读取被明确记为 `test_unavailable`，随后自动恢复。PID 改变则丢弃剩余次数。接口不改变网络规则、原生流量、状态文件、远端服务或正常客户端设置。普通客户端与无效次数的拒绝有单独回归。

这个注入只验证状态读取回退，不能代替物理断网、控制接口整体失效或外网重连验收。
