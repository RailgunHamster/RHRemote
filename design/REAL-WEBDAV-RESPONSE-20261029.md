## 实际链路与结果

目标是 winserver 既有 DAV 服务下新建的唯一目录 `http://192.168.0.104:5244/dav/RHRemote-UI-response-7f9a6589e7db`。读取 Windows 已保存的这一 WebDAV 账户凭据，仅经 ADB 标准输入写入模拟器应用私有文件；传输前核对文件 SHA-256，测试开始即删除。没有将密码写入命令参数、环境变量、报告或日志。

客户端连接仅监听应用 localhost 的故障转发器。转发器严格限制方法和该目录中的 `rhremote-config-v1.json`，实际向既有 DAV 服务发送请求；它不生成服务器文档、不模拟 ETag 或锁，也不访问正常同步文档。

1. 通过原生同步页输入并保存隔离账户，点击“立即同步”，完成首次实际上传。
2. 通过设备名称页修改一个本地显示名称，再次点击“立即同步”。转发器收到服务器成功的 PUT 响应后，另外 GET 实际文档，逐字节 SHA-256 确认它与刚才的 PUT 内容相同，然后只对这一次客户端连接发送 TCP RST。
3. 实际页面显示“同步结果待确认／自动同步已暂停”，保留先前完成时间及同步基准，不冒充本次成功。一次自动同步请求被拦截，没有增加 PUT。
4. 实际重建 Activity 后，同样的待确认信息仍显示。点击原生“立即同步”后，完成重新读取、合并及上传，待确认和自动暂停消失，完成时间推进；实际远端文档与当前规范化共享配置一致。

最终原生用例耗时 **14.953 秒**，`OK (1 test)`。共有 **3 次 PUT、3 次 LOCK、3 次 UNLOCK**；自动请求没有产生第四次写入。页面图来自自身 `View.draw`，没有系统截图或系统输入。

最终证据目录为 `D:\RHRemoteTools\ui-sync-response76-review-20261029\real-service-approved06`：

- `native.log`：原生断言及耗时。
- `response-7f9a6589e7db/result.json`：提交内容核对、待确认、重建、自动阻止、手动恢复及文件恢复结果。
- `response-7f9a6589e7db/result-unconfirmed.png`、`unconfirmed-after-recreation.png`、`manual-retry-completed.png`：实际页面。
- `verification.json`：本机／模拟器文件哈希、正常同步文档前后哈希及独占锁清理结果。

## 恢复和清理

所有测试请求结束后，恢复模拟器的共享文件、原加密同步账户、偏好和原备份。私有凭据输入文件确认不存在。正常同步文档只做前后 GET，SHA-256 均为 `7c649603e2c57a7736169533f51d803f2d631108082be29cb13a0365f3424917`。

Windows 的 `preferences.json`、`webdav-local.json` 前后字节哈希一致。模拟器共享文件仍为 `1be1929793f0ef8e4387292269d0c16a583fcd9f4fdb12b5501086873d59bf9a`，账户仍为 `44136fa355b3678a1146ad16f7e8649e94fb4fc21fe77e8310c060f61caaff8a`。

核对新目录中的随机所有权标记后，取得目录的独占递归锁，PROPFIND 确认仅包含本次标记和测试文档，删除该目录，显式 UNLOCK，随后再次确认目录为 HTTP 404。未删除正常文档、未停止服务。模拟器仍为 1512×1008、density 240、font scale 1.0。

失败记录没有覆盖：第一轮标准输入交付为空、第二轮旧按钮文字导致原生测试失败，随后一次重复测试遇到保留的测试目录／夹具，均不计为通过。初次清理脚本的允许路径数组表达式错误使检查拒绝删除，修正后在独占锁下清理；早期删除后未显式 UNLOCK 导致两次重建返回 423，有限租约结束后才继续。最终清理显式释放锁。以上是隔离测试夹具问题，没有据此修改生产实现。

## 验收边界

这一步证明 Android 在**既有服务真实提交后丢失 TCP 响应**时的界面、持久待确认、页面重建与手动恢复。它不等同于物理断网、进程终止、跨端并发冲突、Windows 实际窗口 HTTPS、Windows 实际自动同步计时、系统后台调度或 OPPO 实机验收。这些剩余范围继续保留在 TODO；完整 UI 目标未完成。本轮未发布安装包。
