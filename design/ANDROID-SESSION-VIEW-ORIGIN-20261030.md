# Android 会话中隐藏控件的回调

后续实际 Game 会话、完整模拟器包及仍失败的深色首帧样本见[当前会话记录](ANDROID-SESSION-CURRENT-CONTROLS-20261030.md)。下文保留本轮控件修正与离屏验证范围。

本地候选 Android preview.114，versionCode 332。Windows 候选仍为 preview.110，日常 preview.101 保持关闭。证据目录：`D:\RHRemoteTools\ui-session-view-origin114-review-20261030`。没有操作 OPPO、连接远程主机或公开发布。

## 问题和修正

实际控件可能在页面切换后仍有待处理回调。原会话面板的按钮只检查是否已销毁，滚动开关和音量也没有检查控件仍属于当前显示的分类。悬浮键盘只检查整体开关、忙碌和遮挡，没有核对该按键是否因窗口缩小而隐藏。旧控件直接触发回调时，会继续调用共享动作。

新增的两个正式控制器／控件 JVM 回归在修改前均失败：隐藏的“直接点击”按钮改变当前会话的指针模式，因缩小而隐藏的 Backspace 仍发送快捷键。原生模拟器随后使用实际安装的 preview.113 再验证；客户端 APK 哈希与上一轮已核对的 preview.113 相同。18 个组合均发现同一问题，共 216 次本应被拒绝的回调到达动作接收端。

现在回调先检查控件是否仍在自己的可见父树中、是否启用，以及面板所属分类是否显示。该规则覆盖普通按钮、滚动开关、音量变化和拖动结束、悬浮键盘。失效的拖动结束仍清除本地 tracking 标志，避免妨碍下一次有效音量操作。共享动作和接口不变；接口调用仍可执行对应的会话功能，不要求先打开特定分类。

面板布局、悬浮按键位置、透明度和当前开关入口保持原样。检查发生在控件事件路径，不增加视频帧处理、网络等待或额外确认步骤。

会话入口继续参考成熟客户端的职责划分：AnyDesk 在会话菜单中分别提供输入类型、屏幕、声音与动作，并区分特殊按键和 Android 键盘；RHRemote 继续保留现有“操作／屏幕／声音”、软件键盘和悬浮键盘入口，没有引入新的菜单层级。[AnyDesk 官方说明](https://support.anydesk.com/docs/anydesk-for-android#control-a-remote-session-on-android)。本次回调归属检查是 RHRemote 自身的修正，不据此推断参考客户端的内部实现。

原生用例保留真实 Button、Switch 和 SeekBar 对象，切换分类、收起、隐藏父树、移除控件、缩小窗口后，直接调用这些对象的回调；音量使用 SeekBar 自己的方向键处理。动作接收端仅记录参数，不发送输入。它们证明原生控件的回调归属，不是物理触屏或真实网络会话。正式 Controller 的状态变化由 JVM 测试另行覆盖。

图像来自本应用的 View.draw；这些原生布局没有附着 Activity／系统窗口。没有使用 OS 截图、系统输入注入或 computer use，没有改动模拟器系统字号和显示覆盖值。普通布局测试的四向滚动等回调不等于远端已收到相应输入；真实会话、外网及 OPPO 验收继续保留。

首次 QA 预检的安装路径字符白名单遗漏包名中的句点，测试尚未启动就被拒绝；修正该预检后运行有效样本，未将预检失败计作产品问题。记录为 `baseline-preflight-rejected.json`。
