## 产品变化与已知代价

原 PcView 在首次获取 GL 渲染器信息时先显示临时 GLSurfaceView，再构建主界面。这个阶段缺少明确加载状态。新增的 RhStartupView 保留原表面、可见状态、完整尺寸及回调，只在上方放置一条随主题变化的原生“正在加载…”文字。缓存路径继续直接构建主界面，不显示该临时提示。没有新增操作按钮或改变连接参数。

四组交替、每次清空隔离应用数据的对照中，基线设备页首次预绘制中位数为 1490.0 ms，候选为 1674.5 ms，增加 184.5 ms；候选加载文字的首次预绘制中位数为 307.5 ms。每组候选减基线的平均差为 156.75 ms；此前进度消息把约 0.16 秒的配对平均差说成中位数，最终记录在此区分。提示让等待可见，但不能据此宣称启动提速或无性能退步。这个额外开销仍需继续处理，未用候选替换日常版本。

这些是生成配置、真实 PcView 的受控模拟器生命周期计时：起点为测试调用启动 Activity，既不是用户点击启动器，也不是视频首帧或物理显示呈现。系统缓存、主机负载和样本量限制结论；所有原始样本和异常值均保留。全套界面流程的 totalRunMs 包含 53 次 HTTP 调用、对话框和截图，不作为启动时间。

## 真实 Release 路径

目标是经过 R8 的非 Debug x86_64 Release，仅使用隔离应用后缀；没有 RhUiFixtureActivity，也没有隔离 tracing／Kotlin 额外保留规则。观察器仅使用 Android 框架 Instrumentation，运行实际 PcView、ComputerManagerService 和生产 HTTP 动作分发。

令牌仅在该进程内读取新生成的隔离私有文件，没有导出令牌、复制正常客户端私有身份或读取被禁止的 Windows 控制令牌。没有配对、开始串流、WebDAV 传输或打开更新安装。

冷启动和缓存路径分别通过一轮 53 次真实 HTTP 调用：搜索／选择设备、修改连接参数、离开保护、继续编辑、放弃、保存并继续、四类应用设置、WebDAV 草稿取消、主题重建及五类连接设置。继续编辑和保存并继续通过本应用实际 Dialog 按钮触发；其他流程使用生产动作接口。主题重建保留设备、搜索和页面，取消未覆盖保存内容。原生对话框和页面均保留自身绘图。

浅深主题都实际捕获到加载文字；冷启动有加载阶段，缓存运行没有。首次预绘制、提示出现和主界面预绘制分别记录，避免把接口通过误认为提示已经显示。
