# Android 网络变化后的设备状态

2026-10-31，记录 167，Android 本地候选 0.2.11-preview.167 / 385。Windows 当前候选仍为 166。设备检查原先只绑定配置和证书，切网后旧请求仍可能把页面改成“在线”；旧网络的丢失通知也可能覆盖新网络状态。

## 页面和动作

现在后台发现和主动检查都记录开始时的默认网络代次。网络变化后返回的旧结果显示“需重新检查”，不计作当前在线或已验证配对；新请求成功后恢复正常。网络变化与地址／配置变化使用不同提示。

原来已确认的认证拒绝、证书不符、仍需重新配对和身份问题继续保留，当前可达性改为待确认，主入口使用“检查连接”。保存的证书不被删除，配置和证书真正改变时旧诊断才按原规则失效。保存身份可经正常连接准备重新验证，普通首次配对的显式入口保持。

Android 的直接动作接口现在使用相同检查结果。`device.connect` 不能绕过“重新配对”或“检查连接”；保留身份错误且网络已变时，`device.pair` 也需先取得新的检查结果。拒绝在创建 admission 和后台准备任务之前发生，按钮与接口的目标 UUID 不变。

## 网络和观察

新增 RhNetworkObservation 仅跟踪进程内默认 Network 对象和代次，不修改线路策略、系统网络绑定或共享配置。相同网络的重复可用通知不会使新结果失效；旧网络丢失时，不再把已经切到新默认网络的设备统一改成离线。

Android 文档将 Network 定义为具体网络连接的标识，断开后不能继续使用，重连会产生新对象。本实现据此隔离观察，而不是按旧 IP 或完成时间判断新鲜度。[Android 网络状态文档](https://developer.android.com/develop/connectivity/network-ops/reading-network-state)

观察在请求开始时绑定，完成得晚不会获得新网络的身份。网络变化还参与行签名，即使原始 OFFLINE 状态没有变化，当前页面仍会重新绑定提示。普通同网络状态不匹配时保留原有短路路径；代次在创建观察时解析，避免重复读取配置。

公共设备 check 结果的 `staleReason` 区分 `network_changed`／`configuration_changed`。仍需处理的身份错误用 `networkStale:true`、`reachabilityCurrent:false` 保留原 outcome；其他旧结果用 `stale:true` 和 `previousObservationId` 表示历史信息。后者不是新的成功证明。这些字段都不进入 Saved、WebDAV 或配对数据库。
