# 客户端交互逐页检查 · 2026-10-27

本轮预览：0.2.11-preview.2。Windows 使用 Rust / Slint；Android 使用原生 View / Java。此文件记录实际检查、实现范围与验证，不能代替远程连接或性能验收。

## 对照来源

- [HelpWire · Client list](https://kb.helpwire.app/client-management/client-list/)：沿用用户选定 D 方向的设备列表、选中详情与固定导航。
- [AnyDesk · Client settings](https://support.anydesk.com/settings)：对照应用设置与会话设置的分类。
- [AnyDesk · Session settings](https://support.anydesk.com/docs/session-settings)：核对屏幕、音频与常用动作的分组。

以下方案是 RHRemote 的实现取舍，不表示逐项复制对方行为。

## 逐页检查与处理

| 页面 | 原问题 / 检查点 | 本轮处理 |
| --- | --- | --- |
| 设备列表 | 看见 192.168 地址容易被理解为只支持局域网；备用地址无法搜索 | 搜索涵盖已保存的备用地址。列表保持简洁，详情明确显示局域网、Tailscale 与内置直连 / 中继配置 |
| 设备详情 | 配置地址与实际使用路径混淆 | “首选地址”与“最近选路”分开显示；没有对应设备的成功选路记录时显示“尚无记录”，不把配置当成已连通证据 |
| 添加电脑 | Android 输错地址后对话框也会关闭；提示只写内网 | 输入校验失败留在原处显示错误；提示支持 IP、主机名、Tailscale 与公网地址 |
| 配对 | 核对 PIN、取消与失败状态入口 | 保留现有配对状态流程；本轮没有对真实主机发起新的配对 |
| 连接过程 | 核对阶段提示、取消入口与离线设备是否仍能尝试备用路径 | 保留现有分阶段连接与取消；未以此轮 UI 验收替代外网串流验收 |
| 设备设置：画面 | 预设分辨率不显示当前选择；修改控件时滚动位置跳动 | 高亮当前预设；Android 同一分类内重绘保持滚动位置 |
| 设备设置：音频 / 输入 / 高级 | 分类按钮像多个主操作；核对控制项是否仍有 API | 分类改为选中态；保留全部设置及共享动作目录 |
| 设备设置：网络 | 保存地址、应用中继地址、保存连接配置是多个提交入口 | 地址、中继与配置统一成为草稿，由底部“保存 / 取消”提交或放弃；诊断使用当前草稿快照，不依赖用户先改写持久配置 |
| 应用设置：更新 | 检查、下载 APK、安装并列；忙碌反馈笼统 | 两端只显示一个主按钮，按状态变更。检查不触发安装；第二次明确点击才下载并进入安装流程；失败在原处重试 |
| 应用设置：配置同步 | 未配置时也能触发同步；Android 忙碌时重复提交；深色下拉框黑字不可读 | 保存为主要操作；未配置或忙碌时禁用不可执行的按钮。修正选择框和弹出菜单的文字、背景、最小高度 |
| 应用设置：外观 / 关于 | 切换主题按钮含糊，关于页混入 GUI 实现语言 | 明确显示将切换到的主题；关于页展示产品、版本与既有统计入口 |
| Windows 导航 | 设置页顶部重复设置、主题、添加电脑，与侧栏重复 | 删除重复顶栏，保留侧栏和页内返回 |
| Android 返回 | 保存或取消设备设置后直接跳到列表 | 返回原选中设备的详情；系统返回与取消一致 |
| 会话悬浮控制 | 对照操作、屏幕、声音分组与展开 / 收起位置 | 本轮核对既有分组与单测，未改变视频、输入或会话面板布局 |

## 更新主按钮状态

| 状态 | 按钮 | 点击结果 |
| --- | --- | --- |
| 未检查 / 已是最新 | 检查更新 | 请求更新清单，展示结果 |
| 发现更新、尚未下载 | 下载并安装 | 下载、校验，然后进入安装 |
| 已下载 | Android：安装更新；Windows：重启并安装 | 使用已下载且校验通过的包 |
| 检查 / 下载 / 校验中 | 检查中 / 下载中 n% / 正在校验等 | 禁止重复提交，仍可切换设置分类 |
| 检查失败 | 重新检查 | 重试更新源 |
| 下载 / 安装失败 | 重试下载并安装 / 重试安装 | 保留可用版本及已校验包，按当前阶段恢复 |

Android 仍由用户在系统安装器中确认；安装权限返回后延续同一安装包。后台自动检查 / 下载不打开安装器。保留 `updates.check`、`updates.download`、`updates.install` 诊断 API，新增 `updates.primary` 与可见按钮完全一致。

Windows 下载使用独立进度快照，不占用普通导航动作队列。通过 HTTP 调用耗时更新时，也不会把状态查询和导航请求排在下载后面；同时只接受一个更新请求。

## 验证范围

- Rust：111 项测试通过（核心 41、Windows UI / 平台 70）。包括主按钮两次明确操作、失败重试、安装阻止远程连接、HTTP 更新期间查询 / 导航、地址草稿原子保存与取消。
- Android：192 项 Release JVM 测试通过。包含实际 View 点击、下载与签名 / 哈希校验、安装权限衔接、重试、按钮不被进度刷新替换，以及深色选择框。
- 独立 Android 35 x86_64 模拟器：横屏 1008×672 dp、竖屏 672×1008 dp、窄屏 360×800 dp / 130% 字体。检查原生按钮边界、最小点击高度和文字裁切；不操作 OPPO。
- Windows 软件 UI 渲染、本地 Velopack 预览包；使用独立配置目录，正式配置哈希前后相同。
- 实际公网更新检查：Windows 从 Gitee 成功读取清单；Android 此轮 Gitee 超时后回退 GitHub 成功。预览版本高于正式版，结果显示“已是最新版本”。
- APK、Windows 安装包及 Portable 已生成。当前仅为本地预览；GitHub / Gitee 正式版本仍为 0.2.10。
