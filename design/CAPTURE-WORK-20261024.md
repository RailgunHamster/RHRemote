## 新的按图像调用跨度

只在至少一个活动会话请求逐帧统计时，为 Desktop Duplication RAM 路径读取以下调用时间：

- `acquire`：释放上一份 duplication frame 并获取下一份。
- `prepare`：表面、格式、鼠标形状检查和 GPU CopyResource 调用返回。
- `image_pool`：等待可复用图像。
- `map`：实际 Map 调用，可能包括资源等待；它是 CPU 墙钟跨度，也包含线程失去调度的时间。
- `image_setup`：已知格式后的 CPU 图像分配／准备。
- `cpu_copy`、`unmap`、`cursor`：实际拷贝、解除映射及需要时的光标合成。

微软文档说明 [CopyResource 是异步调用](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/nf-d3d11-id3d11devicecontext-copyresource)，
因此 prepare 的终点不能称作 GPU 拷贝完成；[Map 的行为受 GPU 资源使用状态及标志影响](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/nf-d3d11-id3d11devicecontext-map)。
统计本身不能把驱动等待、GPU 执行及 CPU 调度分开，必要时还需系统级调度证据。

固定大小元数据写入原图像，复用前清空；按原捕获编号复制到各自会话的 capture_ready 事件。
编码、发送、重复输入不重复序列化该工作量，也不修改像素或视频路径。
活动会话统计关闭时不读取这些新计时时钟。采集线程不分配计时容器、不写文件、不等待统计队列。
未执行阶段、其他捕获后端，以及没有交付图像的超时／失败，均明确保留未知，不补零冒充测量。

分析器兼容旧文件。新的 capture-work/v1 声明要求每次捕获提供 profile 或显式 null；
验证整数类型、阶段顺序、不重叠、整次调用边界及 Map/图像建立/拷贝/Unmap 的实际生命周期。
无效数据使记录不完整，窗口选择也不能隐藏完整文件的该类损坏。
按原捕获编号保存 `captures.csv`、阶段分布及主机 Perfetto 时间线；
必须成功保存这些产物才允许删除不再需要的完整原始记录。仍用于对照的文件继续保留。

24 项主机分析回归、9 项窗口分析回归通过；新增 C++ 时钟 opt-in、未知阶段、事件归属与
真实 writer 队列复制／序列化测试待完整 MSYS2/UCRT64 CI。此时尚未部署新计时或取得新实测结论。
