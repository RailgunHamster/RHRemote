# Windows 配对等待反馈与连接页键盘流程

2026-11-01，本地 UI 源码／测试编译版本 `0.2.11-preview.186`。准备配对、联系主机且尚未显示配对码时增加不定进度提示；配对码就绪后收起提示，继续显示主机端输入说明。日常 Windows 仍未替换，本轮未生成新的正常安装包或公开发布。

## 界面行为

采用现有 Slint ProgressIndicator，不显示完成百分比。参考微软的[进度控件指引](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/progress-controls)：耗时未知的操作使用不定进度反馈，让用户知道当前仍在处理。控件只读，现有取消、重试和返回继续使用共享动作。

本轮先核对了实际 Controller 与页面。取消配对会切到连接页并清空配对码，清理期间显示“正在取消配对／正在清理”，完成后返回原设备。此前仅根据配对页正文推断取消时仍显示启动提示，**该推断不成立**；实际旧版取消页没有这段提示，未据此修改取消逻辑。

生产界面只增加一行等待进度控件。修改前后保留同一测试观察器源码：旧版 52 组检查中，键盘、数据保持和取消提示原本均符合要求，八组准备／联系主机场景缺少本轮新增的进度反馈；新版全部符合检查。不将其描述成八次真实连接故障，也不据此宣布首帧更快。

## 保留的失败与修正

- 首轮测试把已确认配对的测试设备当作未配对设备，查找不存在的“配对”按钮，尚未进入阶段检查；随后明确设置未配对前置状态。
- 后续测试错误地期望取消后留在配对页。实际页面与源码均证明会进入连接页，已修正该检查；同时改为记录适配器收到的真实配对编号，避免把连接尝试编号当作取消后仍连续的协议编号。有效旧版对照为 `baseline186-03`。
- 第一次完整运行清理环境变量时留下了空字符串，三项同步绘图测试因目录无效未进入页面断言。其他绘图程序将空目录当作工作目录，产生 472 个 PNG／JSON，共 40,752,152 字节。经逐文件核对未跟踪、创建时间属于本次运行、静态输出名称及哈希后，仅将这些文件移动到 `full-empty-env186-evidence`，未删除或移动源码。
- 修正运行方式，在新进程确认没有截图目录覆盖后重新执行完整工作区。最终 522 项通过，源码目录没有遗留 PNG／JSON。首次失败日志、原始图片和全部移动清单保留，不用重跑覆盖旧证据。
