# Windows 后台窗口测试：最小化参数的修正

preview.105 更正了前一轮的归因：后台测试命令使用 `SW_MINIMIZE`，会激活 Z 序中的下一顶层窗口。这个副作用可以在没有远端连接、视频解码或远端输入时复现；它污染了之后“恢复／菜单是否抢焦点”的判断。跨进程 owner 关联输入队列的事实仍成立，但不能据前一轮样本将其认定为此故障的必要原因。

证据目录：`D:\RHRemoteTools\ui-local-overlay105-review-20261029`。早期窗口关系试验按[原记录](WINDOWS-OVERLAY-FOCUS-20261029.md)保留，手工 Z 序方案已撤回，没有部署到日常客户端。106 核对原始连接清单后发现本轮三次成功真实会话实际为 25 Mbps；测试脚本只修改同步副本，原“6 Mbps”表述已更正，详见[后续记录](WINDOWS-WINDOW-EVENTS-20261029.md)。

## 依据与采用的改动

微软对 `ShowWindow` 的参数明确定义：6（`SW_MINIMIZE`）最小化并激活下一顶层窗口，7（`SW_SHOWMINNOACTIVE`）最小化且不激活；`ShowWindowAsync` 使用相同参数并将请求排到目标窗口线程。[参数定义](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-showwindow)、[异步接口](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-showwindowasync)

- 隔离测试接口 `view.ui.native-window` 的 `minimize` 改用 7。原有存活子进程、首帧、HWND/PID 与隔离模式检查不变，恢复仍用不激活的参数 4。没有更改用户正常点击系统最小化按钮的行为。
- 撤回 preview.104 的 `overlay_window.rs` 及三种悬浮层的手工 Z 序接入，恢复原来的 native owner。无证据表明保留该重构有收益；其完整源码和二进制保留在证据目录，未覆盖失败样本。
- 控制栏在首次映射前设置串流锚点的位置，首次创建先使用一像素，再按实际 DPI 计算最终布局。这样不必先在默认显示器上映射再定位；与已有键盘初始化方式一致。首次显示失败给出明确状态。
- 保留 104 已修正的窗口创建策略：主窗口适配器先创建，后续工具窗口明确不请求激活，避免用尚未到达 attributes hook 的组件标题分类。

## 另一个失败样本

最终包第一次 `final/source-dark06` 在配对准备阶段失败，服务端未出现配对请求，恢复阶段为 0，整轮仍为失败。设备探测记录有 native list 五秒超时及早期退出；主 UI 后来已进入失败态、无存活原生子进程。旧 runner 恰在终止状态切换时请求取消，得到 422 后跳过了关闭步骤。

读取同一个活进程状态后才正常关闭；`cleanup-recovery.json` 确认没有活动操作、正常退出、服务端授权状态不变。runner 现会复核终止状态，取消与终止竞争时不盲目重发，也不遗漏正常关闭。这不是通过窗口测试，也没有改为跳过产品断言。

新旧引擎目录 253 个文件哈希相同。直接运行未配对的裸 `list` 会按预期拒绝列出游戏；`packaged-readiness` 的 -1 不可解释成已经证明服务器不可达。配对准备失败的完整原因仍在连接验收项；之后两个新进程、新身份的最终包用例成功，不消除该失败。

## 检查与交付边界

- 最终核心 135、Windows UI 221 项通过，另 1 项既有用例忽略。相较 104 减少的四项只属于已撤回的手工 Z 序模块，其余控件／流程断言没有减少；UIA 焦点仍未完成验收。
- 本地探针需显式 `ui-overlay-probe` feature 和隔离测试环境，普通构建目标不包含它。支持最多三轮，有等待期限、实际步骤数、前台守卫、事件记录和子进程退出确认。它没有 UI 草稿、真实 WebDAV 或视频能力，不能用来替代这些验收。
- 另发现生产预览中的主窗口和菜单会在后面绑定原生键盘／失焦处理，替换早期诊断事件回调；空诊断日志不能证明这两类窗口未收到事件。106 已完成合并及当前范围采集，见[后续记录](WINDOWS-WINDOW-EVENTS-20261029.md)。本轮外部前台采样与本地探针的独立事件回调不依赖此日志。
- 真实会话均使用已枚举的 winserver 现有物理主屏，1080p30、实际 25 Mbps、无声。没有远端按键、源端输入探针、业务停服或 OPPO 操作。
