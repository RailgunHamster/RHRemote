## 差异与依据

旧代码通过 `GWLP_HWNDPARENT` 把 Rust/Slint 悬浮层交给另一个进程中的 SDL 串流窗口。Windows 会自动关联有跨线程 owner/owned 关系的输入队列，焦点状态不能按两个独立线程理解。[微软说明](https://devblogs.microsoft.com/oldnewthing/20130607-00/?p=4143)

在相同原生引擎、显示器、物理远端屏幕和恢复命令下，保留旧关系时首次恢复激活；只隐藏悬浮层，或只去掉控制栏的 native owner，均得到不激活的对照。因此，该关系是受测恢复问题的触发因素。尚未证明 Windows 内部延迟激活的全部路径，没有证据将其归因到显卡或解码器。

新 `overlay_window.rs` 只定位当前 UI 进程的窗口，复核锚点 PID，不再建立跨进程 owner。控制栏、键盘和菜单按已有串流窗口的坐标与 Z 序跟随；菜单位于控制栏之上。连续悬浮层保持相对顺序，避免每次轮询互相升降。普通窗口不会因上方存在别的置顶窗口而升级为全局置顶；恢复提示脱离串流 HWND 后也取消置顶。[窗口层级接口](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos)

保留最小化隐藏、会话归属、恢复位置、键盘透明度及点击区域。未用隐藏控件或永久禁用键盘导航取得绿色结果；用户发出远程输入后的主动回到串流窗口仍按原有动作处理。

另修正初始化策略：Slint 的 attributes hook 提供的是应用初始标题，不能用最终组件标题区分窗口。现在先创建主窗口适配器，再为后续工具窗口选择不激活策略。实际四次创建记录为一个 main、三个 overlay；普通模式主窗口允许激活，三个悬浮窗口不请求激活，隔离预览四者均不请求激活。新普通模式启动尚未在日常目录验证。
