# 已有虚拟屏分辨率调整

2026-10-23，启动耗时优化的一个独立改动。

此前统计 `1792743599751-e0788ca53147` 的主机显示准备为 5038.92 ms，worker 为 4997.03 ms。Rust 仅处理分辨率已经匹配的情况；不匹配时，先枚举一次 D3D 捕获输出，再启动 PowerShell 重做显示准备。该连接总首帧 11.823 秒，另有协议就绪至首包 2.208 秒，不能把全部等待都归因于显示准备。

`server/crates/rhremote-host/src/native_display_mode.rs` 在已有交互式 Rust worker 内完成受限的模式调整：

- 仅操作受保护 ownership 文件标记、且硬件 ID 确认为虚拟驱动的唯一活动屏。自动模式仍优先可捕获的物理屏；新建虚拟屏及特殊布局保留原路径。
- 从驱动当前 DEVMODE 出发，枚举并检查目标分辨率的 60 Hz 模式，使用具体 GDI 设备名进行 CDS_TEST 后再临时应用，不写显示注册表。
- 保留位置和旋转；请求不得与其他屏重叠。应用前后重新查询拓扑，其他屏必须保持原样；应用成功后只做一次新鲜的 D3D 捕获输出枚举，不复用旧的捕获索引。
- API 报错也检查实际状态。仅当变化完全符合本次目标时恢复原模式；发现外部并发调整时不盲目覆盖。事务失败返回终止错误，避免再次落到 PowerShell 修改屏幕。
- 统计包含 `modeChanged`、`modeValidationMs`、`modeApplyMs`、`modeVerificationMs` 和 `captureMs`；原有 hostRequest/worker 计时保留。

本地 `cargo +1.92.0 test --locked -p rhremote-host -j4`：21 项通过，包含 11 项模式事务测试；覆盖竖屏、4K、驱动身份、越界/重叠、失败前后状态、捕获失败回滚及并发修改。Release 主机构建成功。单元测试使用故障注入后端，不能代替驱动和实际串流验收；部署与耗时对照结果另行记录。
