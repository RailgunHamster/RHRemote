# Android 主导航与设备列表（preview.120）

主导航和设备行统一显示键盘焦点；设备行填充继续表示选中设备，蓝色边框表示当前键盘目标。状态刷新、追加设备和排序不再让仍存在的设备行失去焦点，已经隐藏的搜索框也不能修改后来页面的搜索条件。所有动作继续使用原共享接口。

## 原因与修正

preview.119 的七项工作区回归有六项失败，真实 PcView 也复现了旧搜索 InputConnection 修改另一页面。搜索监听现在先检查具体 View 是否属于当前可见工作区；正常搜索、空结果和返回设备列表的查询保留仍通过。

设备列表原来在任意顺序变化时先 removeAllViews，再重新挂上全部行。现在按实际行顺序进行最小增删和移动，保留未变的行、选中设备和查询；需要移动焦点行时，只恢复仍属于当前可见列表的目标，不排队抢回后来页面的焦点。行背景只在建立或选中状态变化时重建。

第一轮 JVM 已通过，但模拟器真实宽屏在单纯状态刷新时仍丢焦点。记录确认设备行没有移除（detaches=0），焦点却落回侧栏。临时测量探针随后记录到同一个宽屏工作区经历 1512 → 892 → 1404 像素的测量；892 像素低于当时 700dp 的分栏阈值，临时切换到详情模式、隐藏列表并清掉焦点，最终宽度恢复也无法取回。

原因在外层横向 LinearLayout 的默认文字基线对齐。它的零宽度加权子容器会为了获得基线先进行一次 UNSPECIFIED 测量，然后才按实际可用空间重测。本机 SDK 34 的 LinearLayout.java 1211–1224 行可直接核对该分支；实际运行的是 API 35，运行时宽度记录与完整 Home 回归独立确认了本项目中的行为。不是零宽度，也不是设备行被移除导致这次失败。

外层左右两项都是容器，不需要文字基线对齐；现在明确 body.setBaselineAligned(false)，跳过这次无用探测。新增完整 Home 的状态刷新回归在修正前失败，修正后通过。没有增加等待时间、修改响应式断点或加入定时抢焦点。临时 RHMeasure120 日志只用于外部准备目录的诊断包，最终源码和安装包未保留它。
