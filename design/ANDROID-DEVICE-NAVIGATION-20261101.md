# Android 设备概览的固定导航

2026-11-01，本地隔离候选 preview.182 / 400。设备标题、状态和“概览／连接设置”固定在正文上方；查看底部配置或设备顺序后，可以直接进入当前设备的设置。配色沿用 D 方案。日常安装和公开发布均未替换，完整 UI 目标仍在进行。

## 交互与布局

采用已有 Windows `DeviceContextHeader` 的层级：设备上下文和导航在滚动区域之外，正文独立滚动。宽屏继续显示设备列表；窄屏保留左侧“返回设备”。设置页已有的分类、保存栏和设备切换不变，所有操作继续经过现有动作接口。

参考 Android 官方[列表／详情模式](https://developer.android.com/develop/ui/compose/layouts/adaptive/list-detail)的宽屏双栏、窄屏列表与详情导航，以及[应用栏](https://developer.android.com/develop/ui/views/components/appbar)对位置、重要操作与切换入口的职责划分。Android 仍采用原生 View＋Java，没有引入 Compose。

短窗口会收紧标题区并隐藏副标题；详情宽度足够时，标题和导航并排，让正文仍可阅读。重新变高后恢复完整标题区。同一设备刷新保持正文位置，换设备回到顶部，并清除旧详情的焦点。空设备页不显示无对象的标题和页签。

## 实际验证

| 范围 | 结果 |

| 完整 JVM Debug 回归 | 69 类、634 项，零失败／错误／跳过 |

| 原生实际附着的 RhHome，新 182 | 12 组通过：360×640、640×360、1008×640 dp，两主题、两档字号 |
| 从底部进入设置，切换设备的继续编辑／放弃／保存 | 12 组均通过，核对草稿归属和实际持久值；最短正文可视高度约 159.3 dp |
| 原有详情滚动回归 | 16 组通过，实际设备行／动作接口均检查换设备回顶部、同设备刷新不移动 |
| 预览 | 最终旧／新导航流程 72 张自身绘图；既有滚动回归另 32 张 |

第一版新观察器在进入设置后等待已经 GONE 的设备页布局，触发三秒等待失败。修正为只等待可见设备页后，同一个最终观察器重新运行旧包和新包；旧包仍失败，新包通过，没有延长超时或取消完整可见断言。另保留最初 JVM 的视口坐标检测修正记录：视口边界从父坐标映射，避免将 ScrollView 自身的内容滚动误算成容器移动。

这些检查使用自己应用的 View.draw、按钮 performClick 和共享动作，没有操作系统截图或系统输入。示例设备使用 192.0.2.182／183，没有实际配对、远程连接或 WebDAV 操作。此前 181 的整页灰色及 after 帧差异仍保留原调查；本轮的有意布局改变不用于宣布那项像素问题已解决。
