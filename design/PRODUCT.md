# RHRemote 产品约定

更新：2026-10-21。设计草图保留为历史，当前实现与验证见 IMPLEMENTATION-STATUS.md。

## 已确认

1. Windows 与 Android 都做。
2. 服务端继续用现有 Sunshine，不因客户端重构改变其配置、业务服务或配对凭据。
3. 界面参考 ChatGPT.exe 的现代、克制风格，UI 与用户共同讨论。
4. 既有优先级为 winserver；claw 可以更慢，必要时降低分辨率，不扩容虚拟机。
5. 音频必须有可配置开关、音量、主机继续播放及声道选项；测试期间保持客户端静音，不把测试要求固化成全局禁音。
6. 本机鼠标已交换主副键，平板轻点必须保持“选择 / 打开”的语义，不能要求用户修改电脑的鼠标习惯。
7. Windows 使用 Rust + Slint；Android 使用原生 View + Java。
8. 每个产品按钮有对应操作接口，GUI 与 HTTP 共用分发。设置使用分类 Tab，WebDAV 页填写同步配置。
9. 按客户端实例 × 远程设备独立保存连接参数；本机设备也参与同步、显示和编辑，只禁用连接。设备支持可同步的 DisplayName 别名，保留原始主机名和连接身份。
10. Windows 更新使用 Velopack，Android 下载 APK 后由用户确认安装，发布源为 GitHub 和 Gitee。

## 首版界面提案

### 设备页

直接展示电脑，主要动作是“连接”。设置放在每台电脑旁，按设备保存。Windows 使用侧栏；Android 增大触控区域，并适配横竖屏的界面布局。两端共享颜色、间距、圆角、控件状态和文案。

草图提供“侧栏工作台”和“专注连接”两种布局用于讨论。草图中的状态与点击均为演示，不发起真实连接或修改服务器。

### 设计版本

- **v1**：ChatGPT Windows 风格的中性色方案，原始草图保留。用户反馈整体方向不错，尚未最终确定布局。
- **v2**：用户已确认采用。参考 RHVideo 调整配色：浅蓝灰背景、蓝色主操作、紫色点缀。参考项目只读，未修改 RHVideo。

配色来源及文件哈希见 `rhvideo-palette.json`。浅色方案取自实际加载的 RHVideo 主题；深色方案由同一色系适配，次要文本与状态色适当加深以保证可读性。版本索引见 `REVISIONS.md`。

### 每台电脑的设置

基础区包括别名、尺寸、帧率、码率、编码和触控方式。尺寸、帧率、码率、编码及输入模式属于当前客户端连接这台电脑的配置；Windows、平板和两台安卓设备互不覆盖。设备别名、名称、地址及鼠标左右键事实共用。其他客户端配置只能通过“复制到当前配置”写入草稿，保存后生效。音频开关、音量、声道和主机继续播放按客户端配置保存。

“这台电脑已交换鼠标左右键”用于客户端触控补偿，默认为关闭。本机 RailgunHamster 的草图默认开启，是基于本机已读取的系统设置；winserver 与 claw 不推断其主副键状态。首版可手动选择并按设备记住，不宣称 Sunshine 会自动上报该状态。

### 远程画面

画面占主要区域，工具条按需呼出：直接点击 / 触控板、软键盘、缩放、连接设置和断开。声音可在工具条即时开关和调节音量。统计信息作为可选辅助层，不常驻占据画面。

## 触控语义与实现要求

| 操作 | 期望行为 | 约束 |
| --- | --- | --- |
| 轻点 | 选择、按下按钮 | 根据当前主机的触控补偿映射，不能依赖“物理左键”一定是主键 |
| 双击 | 打开、执行默认动作 | 点击定位与主副键映射一致 |
| 长按 | 上下文菜单 | 等待手势判定，不能先误触发主键操作 |
| 双指平移 | 滚轮滚动 | 多指进入时取消单指点击与长按，避免误拖动 |
| 双指捏合 | 客户端画面缩放 | 与双指滚动按距离变化阈值区分；需真机验证 |
| 放大后移动视区 | “移动画面”模式 | 单指拖动默认仍是远程拖拽；工具条单独切换视区平移 |

补偿仅作用于客户端触控生成的按钮事件；物理鼠标和系统主副键设置保持原有行为。按下、抬起、取消、断开与模式切换必须成对释放，避免卡键。两指滚动是滚轮事件，不描述为按住鼠标中键拖动。

## 与 Sunshine 的兼容边界

复用已验证的发现、PIN 配对、传输、硬件解码和呈现能力。UI 层不改变串流时序，不把界面重写解释为性能提升已经成立。

客户端界面适配横竖屏，与远程 Windows 桌面自动改变方向或分辨率是两件事。自动改变远程源尺寸取决于服务器已有显示策略；在不改 Sunshine 的边界下应协商已有模式，不承诺凭客户端 UI 就能实现源屏自动旋转。

已有实验保留为基线。新版需回归连接、输入、音频控制（测试静音）、分辨率一致性和真实显示帧率；首先验证可用性，再验证 30 / 60 FPS 与 4K。

## 后续界面迭代

- Windows 当前使用侧栏和设备列表，Android 使用顶部设备入口与底部导航。
- 平板点击“控制”呼出底部工具条，提供直接点击 / 触控板、键盘、平移、缩放还原、统计和断开。
- 信息密度与控件视觉可继续依据用户反馈迭代。

## 当前交付状态

Windows Rust 前端与 Android 原生客户端已运行，并以独立应用保留原 Moonlight。两端使用交换主副键的 winserver 做实际输入回归。具体通过项与未完成项见 IMPLEMENTATION-STATUS.md；尚不宣称稳定帧率通过。
