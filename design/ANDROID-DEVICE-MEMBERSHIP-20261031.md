# Android 完整配置恢复与设备列表

2026-10-31，记录 171。本地 Android 候选为 `0.2.11-preview.171 / 389`，Windows 候选保持 166。完整双端 UI 目标继续进行，未替换日常安装或公开发布。

## 行为与范围

已接受的完整配置从 A、B 变成 B 后，Android 工作区原先只添加 B，不移除缓存中的 A；迟到的原生更新也会再次发布 A。下一次 `RhShared.capture` 将全部原生缓存合并，因而可能重新导出 A。现在只记录完整配置替换前后明确移除的 UUID，工作区恢复、发现发布与导出使用同一过滤规则。被移除的选择退到剩余首项；空列表清除选择。

新发现的 C 保持正常出现和导出，包含传输期间才出现的 C。主动通过原有添加页面重新添加 A，或后续完整配置明确包含 A，均可以恢复它。现有成员优先于本机移除记录，保留旧原子文档恢复后的可用性。别名、顺序以及其他客户端的配置组不因此清除。只退出被移除设备的运行时检查和卡片缓存，不删除原生配对数据库、证书或已有会话。

**这不是远端删除同步功能。** 当前 WebDAV 三方合并规定缺项不推断为删除，171 没有改变合并算法或共享格式，也没有新增删除按钮。真实回环验收先验证远端缺 A 时仍保留 A，再在测试的完整配置应用边界注入 B／空列表，验证后续正常同步不会从旧原生缓存带回已移除项。不能将这个受控输入说成用户已能跨端删除设备。

## 实现

- `RhShared.apply` 根据旧、新完整文档计算移除 UUID，保存至本机 `rhremote.global` 的 `removedSharedDevices`，并记录本机初始化标记 `deviceMembershipAuthoritative`；两个字段均不进入共享 JSON。UUID 移除比较不区分大小写。
- 本机记录先持久化，再替换原子文档；记录提交失败不应用新文档。新文档再次包含的 UUID 从记录中清除。类型异常时暂时只接受当前文档中的成员，下次有效应用修复本机记录；可读的既有移除集合继续保留。
- `RhHome.update` 使用已读取的共享快照过滤迟到更新；`restoreSharedDevices` 移除明确退休的缓存行并修复选择，保留未被移除的新发现。`RhShared.capture` 同样跳过退休行，避免下一次导出复活。
- 不新增网络请求或额外共享文档读取。这里没有做性能收益或首帧优化声明，也不能从旧版本已重新导出的列表推断过去删除意图。
