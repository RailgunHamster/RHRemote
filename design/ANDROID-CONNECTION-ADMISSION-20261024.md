# Android 连接入口的取消与资源交接

原先 RhHome 在选路期间只设置 networkBusy。动作分派中的 stream.disconnect 仅查找串流或恢复任务，
无法取消仍在首页的连接。选路结束又提前清除 networkBusy，PcView 单独开线程查询应用列表，
迟到结果仍可能打开 Game。同步和 APK 下载也共用这个只有两个线程的队列。

## 当前实现

- RhAdmission 从选路、配对状态确认、应用列表查询，一直持有连接占用到清理完成或 Game 接管。
  首页的“取消连接”、返回键及既有 stream.disconnect 动作进入同一分派；配对保留 pair.cancel。
  状态接口提供 phase、attemptId、workerRunning、pairing、cleanupPending。取消立即生效，
  UI 不等 Java 隧道启动锁；真实工作和清理未结束前仍禁止下一次连接。
- 独立的连接线程处理入口及清理，不排在 WebDAV 或 APK 下载队列后面。
- Rust JNI 使用单调递增的尝试编号和独立取消标志。取消先于 JNI 注册时仍有效；迟到的旧编号
  不会取消较新的尝试。Client 等待端点和连接时检查取消，失败后关闭已创建的端点再返回。
  这个编号用于同一进程中的任务归属，不替代 Sunshine 证书或动作 API 的鉴权。
- NvHTTP 拒绝取消后才创建的请求；已返回响应头的 Call 仍跟踪到正文关闭，不能只依赖
  OkHttp dispatcher.cancelAll。各实例只取消自己的请求。
- 配对主线程结束后，还等待按次签名取消的后台请求结束，才清理临时隧道。
  等待任务结束不等于主机必定确认了取消；原来的有限重试和完成后不撤销配对的语义保留。
- Game Intent 携带一次交接编号，核对设备 UUID，最多接管一次。取消后的迟到窗口直接结束，
  并在 pause / stop / destroy / focus 生命周期中跳过未初始化的输入和恢复组件。
  已接管的 Intent 移除这个字段，后续媒体恢复沿用独立的恢复状态。
- 测试统计增加连接入口阶段、取消、交接和清理时间；界面区分检查地址、确认配对和读取应用列表。
  清理失败会关闭统计并保持连接占用，不虚报已释放。

## 验证范围

完整 86 项 JVM 测试零失败，包含 15 项入口状态及 UI / 动作分派测试、两项实际 PcView / ServerHelper
交接测试、Java 启动锁/JNI 取消边界、真实 loopback TLS 的取消前请求及取消响应正文，
以及既有的配对、证书、VPN、恢复和界面回归。实际 Game 的拒绝启动生命周期已执行到销毁。
两线程后台队列被测试闩锁占满后，连接仍进入独立线程；测试闩锁不依赖超时自行释放。

Rust transport 的 11 项测试通过，包括取消编号、实际连接等待中取消及端点收尾。
Android ARM64 Rust 库、APK 和测试 APK 均构建成功，库导出所需 cancelStartNative 等 JNI 符号。
构建日志为 `D:\RHRemoteTools\build-android-admission-isolated-v025-20261024.log` 及最终复核日志。

本地开发包为 0.2.5 / code207，尚未发布或安装。正式更新仍为 Android 0.2.4、Windows 0.2.3。
没有操作 OPPO，也没有重启或替换服务器。以上不是 ARM 真机、蜂窝视频、输入或网络切换的验收。

## 继续检查

当前工作覆盖初次连接入口。现有媒体恢复仍在发出新 Game 之前释放恢复占用，直到新控制器安装
之间存在交接空隙；它也尚未接入本次按次 JNI 取消信号。另需检查打洞实际形成中继后，若本路径
不接受中继而转向其他路径，临时通道是否及时关闭。这两项继续按 P0 修复和回归，不能将本次
入口测试作为完整媒体恢复或所有回退路径的证据。
