# 未保存选择与错误输入的编辑状态

Android 本地候选 `0.2.11-preview.75` / versionCode 293，Windows 延续 preview.74。证据目录：`D:\RHRemoteTools\ui-draft-ime75-review-20261029`。未发布，未操作 OPPO 或 Windows 桌面。

## 真实失败

preview.74 的真实 PcView 中，连接设置输入非法宽度，然后离开并选择“保存并继续”：错误字段和草稿保留，但 IME 在动画结束后隐藏。`baseline-cases.json` 记录继续编辑、放弃、合法保存通过；非法保存明确失败。没有把最初怀疑的对话框返焦点时序当作已经证实的原因。

原因是 settings.save 的失败分支无条件重建整个表单，移除仍在使用的 EditText，原输入连接随之失效。错误文字定位本身并不等于键盘已恢复。[Android 官方说明](https://developer.android.com/develop/ui/views/touch-and-input/keyboard-input/visibility) 要求同时考虑编辑器和窗口焦点；本轮用实际 IME 可见性及动画完成核对结果。

加强可见区域断言后，真实横屏中又发现音量输入框只有 51 / 72 px 可见，下沿被固定保存栏裁切。`20261029-draft75-layout02-stay/editor-layout.json` 和自身渲染图记录了编辑器、保存按钮及 IME 底部占用。原滚动位置在键盘弹出前计算，视口缩短后没有重新露出当前编辑器。

## 修改

- 错误仍在当前分类时刷新原控件和错误提示，保留输入框、光标及输入连接。
- 必须跳到其他分类纠错时，定位新的错误字段；仅在保存前键盘已打开的情况下恢复键盘，用户已收起时不主动弹出。
- 错误定位的延迟回调归属于当前设备、分类和字段；编辑、导航、后台或销毁会取消旧请求。没有后台轮询或固定延时。
- 可见滚动区域尺寸改变时，在当前键盘可见的前提下露出正在编辑的字段。保存栏保持固定；普通滚动不触发这一逻辑。
- 成功保存与放弃仍进入目的页面，继续编辑不提交；非法保存仍阻止跳转和落盘。共享动作和实际按钮走同一路径。

## 验证状态

视口修正后的完整 Android 单元回归 388 项、最终表单定向回归 19 项通过，包含输入框／光标保留和旧定位不能夺取新页面焦点。最终错误定位使用普通 requestFocus，保留现有键盘导航模式，不强制切入触摸模式。

`native-matrix-final.json` 的 **42 例全部通过**：1512×1008、1008×1512、540×1200／1.3 字体，分别使用浅深两主题，各验证七条真实 PcView 路径。

| 路径 | 验证结果 |
| --- | --- |
| 继续编辑 | 保留原草稿、焦点和已打开的 IME，不提交 |
| 放弃更改 | 进入更新页，IME 隐藏，持久参数不变 |
| 保存并继续 | 进入更新页，IME 隐藏，只保存当前设备明确修改的音量 |
| 非法输入后保存并继续 | 阻止跳转、定位错误字段，保留输入与 IME，不落盘 |
| 当前页直接保存非法输入 | 保留编辑器、原输入与 IME，显示错误 |
| 错误位于其他分类 | 返回错误分类并聚焦字段，恢复此前已打开的 IME |
| 保存前手动收起 IME | 错误定位后仍保持收起，不主动弹出 |

检查依据为实际 View／对话框按钮、共享动作结果、持久文件、IME 可见性和动画结束，以及编辑器和固定保存按钮的完整可见矩形。横屏音量框由 **51 / 72 px** 恢复为 **72 / 72 px**。宽度、主题和字号使用真实模拟器配置，不用布局夹具代替原生 IME。

每例结束恢复共享配置和独立外观偏好；最终回到 1512×1008、density 240、font_scale 1.0，共享文件 SHA-256 与测试前相同：`1be1929793f0ef8e4387292269d0c16a583fcd9f4fdb12b5501086873d59bf9a`。未修改 WebDAV 账户、配对或被控机服务，没有启动远程会话或采集声音。
