# Android 更新安装流程

用户在 OPPO 的 0.2.3 更新页看到“发现新版本／尚未下载”，点击“安装更新”没有明显反馈。
代码中该按钮始终可点，但安装动作只接受已下载的 APK，未下载时立即抛出“尚未下载更新”；
异常只写入页面底部状态，没有在更新区域显示，因此用户看起来像没有操作成功。
这是已确认的应用逻辑问题，不能据此认定用户拒绝了系统安装权限。

## 本次改动

所有按钮仍使用既有动作接口。`updates.install` 在工作线程完成检查、必要的下载和完整校验，
再由主线程打开系统界面。主按钮根据状态显示“下载并安装”或“安装更新”；检查与下载按钮在任务期间禁用。
更新页显示百分比及校验状态，失败原因保留在该页，并对手动操作显示 Toast。

下载使用临时文件，仅在长度、SHA-256、包名、版本和当前应用签名均通过后替换缓存并保存记录。
重开应用可以恢复待安装状态，安装前仍会重新完整校验。检查更新时可复用相同版本的完整缓存。
活动在横竖屏切换时复用现有 RhHome，避免丢失下载和连接任务的状态。

Android 8 及以上先检查当前应用是否允许安装其他应用，缺少权限时打开应用专属设置。
返回后允许则继续校验安装，拒绝则保留 APK 和可重试状态，不反复弹出设置。
系统安装器收到 FileProvider content URI、临时读取权限和 ClipData，用户仍需手动确认。
后台自动检查／下载从不自动打开权限设置或安装界面。

## 验证范围

`RhUpdateInstallTest` 使用真实 RhUpdates / RhHome、文件哈希、Android 包管理器信息、
动作分派和系统 Intent；HTTP 内容与 APK 解析结果使用无生产密钥的测试夹具。
AndroidX FileProvider 的根目录比较硬编码 `/`，Windows JVM 的规范路径使用 `\`；
测试仅将该私有比较替换为宿主 Path 比较，保留真实声明解析、根目录选择和 URI 生成。
覆盖发现更新但未下载、缓存复用与损坏、包名／版本／签名错误、权限允许／拒绝／重建、
取消安装后重试、主按钮及接口一致性、下载中重复操作、横竖屏状态复用、错误提示、
安装器不存在以及后台下载不弹窗。

2026-10-24 完整 102 项 JVM 测试零失败，其中安装流程新增 16 项；
ARM64 应用 APK、测试 APK 构建通过，9 项发布前置测试通过。
构建日志：`D:\RHRemoteTools\build-android-update-install-tests-20261024.log`。

OPPO 自动测试仍按用户要求暂停，不能将 JVM 结果当作其系统安装器或实际外网媒体已经验收。
