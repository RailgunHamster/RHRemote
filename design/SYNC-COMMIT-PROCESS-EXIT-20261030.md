# WebDAV 提交及本机保存阶段的进程退出恢复

Windows 后续的五个对应进程中断点已通过正式 ConfigSync／Controller、实际文件和既有 DAV 服务验证，见[Windows 记录](WINDOWS-SYNC-PROCESS-EXIT-20261030.md)。该测试使用专用测试可执行文件及软件控件后端，保留正常客户端运行与原生设备恢复的验收边界。下文记录 Android 实测。

使用专用 emulator-5580、既有 winserver DAV 服务和每轮唯一的隔离目录，完成五个保存边界的真实进程退出／重新打开验证。正常 DAV 文档只读，没有操作 OPPO、日常 Windows 客户端或业务服务。证据目录为 `D:\RHRemoteTools\ui-sync-commit109-review-20261030`。

测试在指定位置主动退出专用测试进程，重新运行时 PID 必须不同；这不是只重建 Activity。先关闭本轮窗口以避免 Android 自动重新打开，再在真实网络／文件边界退出。此结果不代表断电持久性或系统所有杀进程方式。

前四类本机边界使用的 preview.109 与 Android preview.110 在同步实现上仅有 HTTP 423 提示文字差异。提交响应前的旧文案对照 `commit-eaa7b4fa993c` 也完整通过，随后以 preview.110 核对新提示及同一恢复路径。

每轮先通过原生表单保存隔离账户并完成一次同步，再经设备名称控件编辑一台设备；另一个测试参与方在同一隔离文档中更改第二台设备名称和主题。实际同步必须合并两边的不同更改。提交后的服务器文件由转发器和本机测试控制器分别 GET／核对 SHA-256；没有模拟服务端文档、ETag 或锁。

应用内故障转发器只监听 localhost，只允许该唯一目录的同步文档和指定 DAV 方法。应用阶段通过测试 Context／File 包装在原始文件路径上截取边界；生产 APK 不包含这些测试类，也没有新增产品退出接口。

## 冷启动界面与重试

五轮均验证：

- 冷启动读取真实任务日志及加密的隔离账户；界面显示“结果待确认／自动同步已暂停”，不把中断显示为本轮成功。
- 一次自动同步调用被跳过，转发器没有收到 GET／PUT。编辑地址后取消仍保留提示；实际主题切换重建 Activity 后提示仍存在，两种主题均有自身 View.draw 图。
- 用户经原生“立即同步”按钮重试。合并两边的设备名称，远端与当前规范化配置相同；只有完成后才解除自动暂停。没有清空旧基准来掩盖冲突。
- 每轮重新打开后的手动恢复只有一次成功 PUT；正常本地 DAV 账户始终未替换，真实凭据只经标准输入进入应用私有文件，测试开始即删除。

响应送达前退出会留下本轮自己的锁。立即手动重试实际收到 HTTP 423，维持待确认和自动暂停；测试按服务端 XML 返回的 60 秒租约等待自然到期，再通过按钮重试。preview.110 轮实际等待约 **52.96 秒**；没有缩短租约、接管其他锁或给产品添加自动重试循环。

## HTTP 423 提示修正

旧两端把 HTTP 423 一律解释为“另一台设备正在同步”，这与本轮自己的遗留锁不符。preview.110 统一改为“WebDAV 文件被占用，请稍后重试（HTTP 423）”。423 表示资源被锁，并不证明锁属于另一台设备。[RFC 4918 §11.3](https://www.rfc-editor.org/rfc/rfc4918#section-11.3)

Android 426 项 JVM 回归通过；Windows Core 135／UI 226 项通过，另有一项既有忽略。Windows 真实 TLS 测试覆盖 401／423／超时分类及原状态保留；Android preview.110 的实际遗留锁页面核对了新文字及后续恢复。Windows 的物理窗口同步复验本轮未做。

## 恢复与保留的失败

每轮实际进程退出后才恢复 14 份设备、身份、数据库及偏好文件，同时恢复原同步备份目录。正常 Windows 配置／账户、正常同步文档 SHA-256 不变。核对新目录所有权标记，持有目录独占锁并检查仅含标记和测试文档后删除，再显式 UNLOCK 和核对 HTTP 404。私有输入及隔离账户均清理。

最早两轮 `commit-5827cdf27078`／`commit-a2b220c45bf3` 是未加入远端主题变更的先期通过样本。`commit-66082c3b5490` 因测试只读取 Timeout 响应头、没有解析服务器 XML 中的租约而失败；其原记录保留为失败，14 份文件已恢复。自己的租约到期后，通过单独的 `cleanup-recovery-*.json` 记录完成该唯一目录的清理，没有覆盖原失败。修正只在测试转发器，产品租约没有更改。

prepare 日志中的 `Process crashed` 是测试主动退出的预期外部表现，不能单凭该文字判定通过。通过依据是边界核对、独立远端 GET、PID 改变、verify 阶段 `OK (1 test)`、界面／重试断言及恢复清理证据。完整 UI、Windows 相应进程退出、OPPO、真实外网和调度边界继续保留在 TODO。
