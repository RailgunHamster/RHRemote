# Android 未保存表单重建恢复（preview.116）

这次修正的是实际交互：系统重建界面后，仍在编辑的连接参数、设备名称和 WebDAV 设置不再无提示地恢复成已保存值。设备选择、搜索、分类、表单错误及未保存确认继续属于原来的操作。

参照 [Android 状态恢复说明](https://developer.android.com/topic/libraries/architecture/saving-states)，配置变化后的页面应保留用户正在编辑的状态。沿用 PcView 已有的内存保留对象，不新增 GUI 框架或依赖。

## 复现与原因

preview.115 的 `saveNavigation` 保存页签、设备与搜索；`retainUiState` 只保留添加地址、复制预览和连接结果。新 Home 重建设置页时重新加载已保存配置，丢失未提交的参数、名称及 WebDAV 输入。

三个新增回归在原实现全部失败：连接表单的空宽度输入消失、未保存名称变为空字符串、WebDAV 地址回到原值。原始结果保留为证据目录的 `baseline115.xml`。

首次修正后，真实 PcView 的两档字号均保住草稿和确认，但原生图片发现 WebDAV 的表单错误又消失了。最初回归没有覆盖 `RhHome.resumed()`；补齐实际生命周期后，`sync-resume-baseline116.xml` 明确复现错误从“WebDAV 请使用 HTTP 或 HTTPS 地址”变为空字符串。

原因是新 Home 的同步状态版本从 -1 开始，恢复到前台时重新处理同一个后台状态，将刚恢复的本地校验错误覆盖。最终实现记住草稿对应的后台版本：版本未变时保留本地错误，后台已有新版本时采用新状态，并继续接收后续变化。

## 最终行为

- 非法、未完成的数字文本与其他参数共同保留，不先转成已保存值；原错误字段、设备地址、别名和复制提示也保留。
- 未保存确认在新窗口重新建立。继续编辑、保存后继续、放弃更改仍走原共享动作，旧窗口的事件不能处理新决定。
- 草稿只恢复到对应设备和页面；保留对象只使用一次，不能在放弃或切换设备后再次套用。
- 外观切换仍按用户的保存／放弃决定处理，不用重建恢复把已经放弃的草稿复活。
- WebDAV 未提交的输入仅在进程内传递。内存对象不持有 Activity 或 View，不写入 Bundle、配置文件、同步文档或控制接口；公共状态继续隐藏密码。没有保留对象的冷启动不恢复未提交密码。
- 新增行为没有新按钮，继续使用现有表单、导航和确认 API；没有改动 Windows、服务器、传输、解码、画质或连接质量策略。

## 最终验证

完整 439 项 JVM 通过，其中 8 项新增测试覆盖三类草稿、页面恢复后的同步错误、较新后台状态、不同设备、重复使用旧保留对象、外观放弃和系统 Bundle 的边界。

专用模拟器最终包完成正常字号、200% 字号两轮真实 PcView 验证；每轮含浅／深主题的三类表单，共 12 个流程和 12 次实际 Activity 销毁重建：

| 表单 | 真实控件及后续操作 |
| --- | --- |
| 连接设置 | 空宽度与码率同时保留，错误及未保存确认恢复；旧编辑器／旧确认拒绝；当前控件修正后保存成功 |
| 设备名称 | 名称及未保存确认恢复；放弃后不改变别名 |
| WebDAV | 地址、用户名、掩码密码和保存错误恢复；继续编辑、取消正常；状态 API 不包含密码 |

每次重建均核对原设备和搜索条件。两轮最终运行均恢复了模拟器原 15 个配置／身份文件、原备份及系统字号，测试进程已退出。未操作 OPPO、日常 Windows、现有 WebDAV 服务器或远程串流。
