# Android 启动探测的按需绘制

2026-11-01，Android 本地候选 `0.2.11-preview.194 / 412`，Windows 保持 188。当前是 UI 改造增量，整体目标未完成，未发布或升级日常安装。

## 改动与依据

PcView 的临时 GLSurfaceView 只在 onSurfaceCreated 获取 GL_RENDERER，onDrawFrame 为空，但默认仍按连续模式渲染。准备脚本现于 setRenderer 之后设置 RENDERMODE_WHEN_DIRTY，保留 193 的主题加载文字、原始可见表面、尺寸、GL 查询、缓存和正常界面构建流程。缓存已存在时继续使用原来的直接初始化分支。

[Android 官方 GLSurfaceView 文档](https://developer.android.com/reference/android/opengl/GLSurfaceView#setRenderMode(int))说明：默认模式反复绘制，按需模式在表面创建或显式请求时绘制，并要求在 setRenderer 之后设置。这里针对启动探测，不改变远程视频显示路径。

本轮观察器直接读取真实表面的公开 getRenderMode：两份基线为 1，194 为 0。未用源码文本断言代替运行状态。暖启动没有临时 GL 表面，缓存路径验证通过。

中途一次只读 pm path 失败，原测试进程已明确终止；随后 get-state、pm path 和 package 服务检查恢复。保留七个已完成样本，只补五个未启动样本，没有重启 ADB、模拟器或业务服务。恢复记录与原失败、补跑日志均保留。
