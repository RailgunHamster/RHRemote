# Android 设置页恢复正文空间

2026-11-01，本地隔离候选 preview.183 / 401。中等宽度窗口改用侧边导航，窄屏设备设置删除重复占行的“连接设置”标题。短横屏中的正文和固定保存／更新按钮重新可见；日常版本没有替换，完整 UI 与交付仍未完成。

## 问题和改动

182 的实际附着页面显示：640×360 dp 窗口继续使用顶部品牌栏和底部导航，设备页再叠加设备选择、重复标题、分类和保存栏，正文会被挤到 0。大字号时保存按钮也会部分裁切。此前 182 的导航检查覆盖了从概览进入设置和草稿选择，没有证明这类窗口中所有设置字段可见；本轮补上该范围。

参照 Android 官方[响应式导航](https://developer.android.com/develop/ui/views/layout/build-responsive-navigation)：紧凑窗口使用底部导航，中等窗口使用侧边导航，布局改变保持同一导航目的地与状态。代码以当前可用宽度 600 dp 为侧栏起点，原有 1180 dp 的展开侧栏保留；不依据设备型号或键盘高度切换导航。

- 侧栏使用可滚动容器，在高度不足时仍能访问下方入口。
- 设备设置的窄屏标题区只保留“概览”、当前设备选择和分类，删除重复标题行。
- 保留固定分类、保存栏、宽屏设备列表、设备选择和未保存保护；按钮继续使用原动作接口。
- 尺寸变化不创建新页面，不替换正在编辑的正文控件，不改保存值或草稿。

原生页面以 360×640、640×360 dp 起始，覆盖两种主题和两档字号，测试过程中调整应用窗口大小。不是 OPPO 实机旋转、真实外接键盘或物理输入法验收。键盘 Insets 的保留检查是 JVM 受控输入，不能替代真实系统键盘。

第一轮新增测试有 Insets 参数数量编译错误，修正后旧版明确复现正文 0 和 600 dp 未使用侧栏。第一轮完整回归还发现已有手动布局夹具在宽度改变、重建分类／保存控件后，没有测量新子控件，读到保存按钮高度 0。夹具保持原四轮测量和至少 48 dp 的断言，改为每轮递归标记布局；最终完整回归通过。原生窗口也补查每次重建后的正文与保存按钮，不能仅靠更改测试消除失败。原编译错误、完整回归失败和细化后的诊断结果均保留。

所有图像为应用自身 View.draw。没有操作系统截图或输入注入，没有真实远程连接、WebDAV／更新网络请求或配对。此前 181 的整页灰色及 after 帧差异仍未解决，不使用本轮有意改变的布局推断其根因。
