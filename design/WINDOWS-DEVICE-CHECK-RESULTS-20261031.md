# Windows 设备检查结果与操作

2026-10-31，本地候选 preview.145。设备检查不再只用原生程序退出码判断是否配对；较长的说明可换行，卡片给按钮保留底部间距。日常客户端仍为 101，Android 仍为 129；未安装、公开发布或操作 OPPO。

## 状态与主操作

| 检查事实 | 页面状态 | 主操作 |
| --- | --- | --- |
| 固定证书的 HTTPS 返回已配对，UUID 正确 | 已配对 | 连接 |
| 完成本机身份查找后没有该主机证书，或 HTTPS 明确返回未配对 | 未配对／需要重新配对 | 配对／重新配对 |
| HTTPS 明确返回认证拒绝，排除了本地 TLS／证书错误 | 认证失败 | 重新配对 |
| 明确观察到对端证书不同于已保存证书 | 证书不符 | 确认目标设备后重新配对，原身份文件保留 |
| TLS 握手失败，无法确认是证书变化还是其他 TLS 原因 | 安全连接失败 | 已保存配对时可重试连接；不据此清除配对 |
| 返回 UUID 不符或设备信息无效 | 设备标识不符／设备信息无效 | 检查连接；API 同样阻止当前记录的连接与配对 |
| 当前线路不可达、原生检查超时或其他未确认错误 | 暂时无法连接／检查超时／状态未确认 | 有本机配对时允许重试连接，否则检查连接 |

“已保存配对”与“本次已验证配对”分开。改变地址或网络策略会清除旧诊断，改别名、画质不清除。诊断只在本次运行中保存，不进入 Saved 或 WebDAV 文档；配对成功会清除旧失败。

## 结果来源与归属

`rhprobe.h` 观察原有 serverinfo 请求，不另外发起一轮相同请求。报告有本次随机编号、目标 UUID、实际 UUID、HTTP／HTTPS 来源、本机证书是否存在、本机身份查找是否完成、分类与耗时。Rust 对报告大小、版本、编号、UUID 和分类所需证据逐项验证，拒绝不一致或过期报告。

不能只看第一次 HTTP 请求就断言本机没有配对：添加地址时，Moonlight 会在读取 UUID 后查找已保存证书，再进行 HTTPS 请求。现在等待最终选中主机、完成该查找后才确认“没有证书”；已存在证书时不把第一轮 HTTP 的临时状态发布成未配对。

原生库把部分证书／TLS 错误也转成 401。新观察字段在固定证书比较和 TLS 错误的产生位置记录原因，区分它们与主机明确的认证拒绝，未依据异常文案猜测，也未改变证书校验、HTTP 回退或请求重试。没有主机证书的检查不再进入只适合已配对主机的附加网络信息分支。

原生报告在附加 `/v1/network` 查询前可用；Rust 能先发布配对事实，再接收可选网络信息。后面的进程／元数据超时不覆盖已经取得的配对、认证、证书或身份结果。刷新快照允许同一次检查继续补充元数据，同时继续拒绝用户改地址、改策略或新配对之后的旧结果。报告文件只清理本次生成的路径，其他尝试和身份文件不受影响。

旧引擎没有结构化报告时保留成功退出的兼容路径；通用失败继续算未确认，不当作明确未配对。完整分类需要候选随附的新原生组件。

公共状态 `deviceChecks` 只包含阶段、结果、来源、本机证书存在标记和 `elapsedUs`。阶段为 `route_selection`、`server_info` 或 `native_process`，耗时属于对应阶段，不是远程首帧或整个进程启动时间。原生报告的 `server_info` 时间属于最终那次调用；递归发现 HTTPS 端口的前一轮请求不合并进该数值。
