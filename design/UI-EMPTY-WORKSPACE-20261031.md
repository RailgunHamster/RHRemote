# 空设备页与搜索恢复

2026-10-31，记录 172。Windows 和 Android 本地候选均为 `0.2.11-preview.172`，Android versionCode 为 390。未替换日常客户端、操作 OPPO 或公开发布，完整 UI 目标继续进行。

## 用户流程

延续既定 HelpWire 设备工作区与 D 配色，补齐空状态的下一步。参照 [Stack Overflow Design System 的空状态规范](https://stackoverflow.design/system/components/empty-states)：无数据与搜索无结果分别说明，能恢复时提供直接动作。这里只借鉴这条交互规则，不将 RHRemote 的配对、同步或更新说成参考产品的功能。

| 状态 | 页面与操作 | 操作后 |
| --- | --- | --- |
| 尚未添加设备 | Windows 保留原有添加入口；Android 窄屏列表或宽屏右侧提供“添加电脑” | 进入现有添加地址页，不直接访问主机；取消返回设备页 |
| 搜索无结果 | 两端显示“没有匹配的设备”和“清除搜索” | 清空本机搜索，恢复原设备列表，保留当前选择与配置 |
| 设备离线 | 保留设备卡片、地址和状态 | 可继续选择、检查或编辑，不显示成无设备 |
| 宽屏连接设置内搜索无结果 | 左侧提供相同的清除动作 | 保持当前设置页和未保存输入，不触发保存或连接 |

Android 没有设备时不再保留空白“概览”分类。宽屏只在右侧突出添加动作，窄屏在列表中提供动作，避免两处同时强调添加。列表为空时也不会因为残留的搜索文字误判为“已有设备但没有匹配”。

## 动作与状态

新增共享动作 `devices.filter.clear {expectedQuery}`。两端校验参数是当前搜索的字符串快照，匹配才清空；缺失、错误类型或过期值不改变当前查询。按钮携带当次查询，旧按压在查询改变、控件隐藏后不会清掉新输入。原有 `devices.filter {query}` 继续用于编辑搜索。

添加按钮复用 `device.add.open`。清除属于本机视图操作，不改变设备顺序、别名、配对、WebDAV、连接参数或设置草稿；Windows 通过已有本机输入分发即时处理，Android 使用相同 Home 动作入口。新增动作已列入共享动作目录，两端按钮和接口执行同一逻辑。
