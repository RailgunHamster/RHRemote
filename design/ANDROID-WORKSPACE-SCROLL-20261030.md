# Android 设备列表的焦点与滚动（preview.121）

沿用已有原生列表和共享动作，补齐“定位一台设备 → 排序 → 继续键盘浏览 → 搜索”的操作上下文。键盘焦点和选中设备保持不同语义：方向键移动焦点并带动列表滚动，Enter 才选择；排序后焦点行应进入视口，转到搜索后不再滚向旧设备行。

## 两个实际失败

preview.120 已保住焦点，但窄屏 200% 字号的原生窗口中，排序后的设备行高度 209 像素，实际可见区域只有 77 像素。旧主 APK 配合新原生用例再次复现，见 workspace-scroll121-baseline120-narrow2/instrument.log 和该轮自身绘制的 row-focus-light.png。

另一条时序是排序后、下一次布局前转到搜索框。移除并重新添加焦点行会触发 ScrollView 的延迟显示；即使焦点已经转移，旧目标仍让列表从偏移 990 跳回 0。新增十一项工作区回归在旧代码有一项因此失败。单独的 JVM“排序后显示”用例原本通过，不能据此声称真实窗口没有裁切。

## 原因与修正

排序现在保留焦点行本身的挂载，通过调整其他行的位置完成顺序变化，不移除再重新聚焦同一个目标。仅当焦点行的列表索引实际变化，才在列表布局完成后通过 requestRectangleOnScreen 显示它；到那时仍须有焦点、允许焦点显示并属于当前可见工作区。只更新在线状态或在尾部追加设备不会因此拉回滚动位置。

第一版修正仍在真实窗口失败。外部诊断包记录到排序反馈出现后列表高度从 372 缩到 295 像素；布局后的请求已将偏移从 55 改为 0，随后 computeScroll 又按 55、86、105 等值推进到 132。焦点行此时已经位于列表顶端，旧动画仍在按之前的坐标移动。

本机 SDK 34 的 ScrollView 源码中，onSizeChanged 在子项新布局前根据原坐标调用 doScrollY；smoothScrollBy 的动画会继续在 computeScroll 中推进，直接请求立即滚动不会清掉旧动画。API 35 上的尺寸与 computeScroll 探针独立确认了本项目实际发生的覆盖。

最终在这一次排序布局的矩形显示请求之后，使用同一个 ScrollView 的 smoothScrollTo 将动画目标更新为当前正确位置。保留正常的方向键及手势滚动，没有全局关闭动画、固定延时、反射修改系统字段或排队重新抓焦点。临时 RHScroll121 探针只存在于外部诊断包；正式 overlay 和最终准备源码均不保留它。

## 验证

最终 469 项 JVM 全部通过，0 失败、0 跳过。宽屏 1512×1008／窄屏 540×960、正常／200% 字号四轮，各含浅深主题九条流程，共 72 条通过。每轮从首行走到末行再返回，排序后的焦点行和方向键到达的每一行均检查完整可见区域；24 份状态／追加／排序记录中的焦点行移除次数均为零。它们不是逐行强制聚焦的替代测试。

前三轮恢复一次通过；最后一轮功能测试已通过，但外层恢复遇到 ADB shell 命令失败。通道恢复后，在应用仍关闭的情况下从该轮原私有备份续做恢复，15 文件指纹、原备份、字号、1512×1008 显示覆盖与密度再次实测一致。保留 verification-first-attempt.json 和 restoration-retry.json，不将首次恢复失败改写为不存在；未重启模拟器、ADB 服务或结束应用。最终核对又读取当前 15 文件指纹，71 项检查通过，见 final-verification.json。

preview.html 包含 32 张最终自身绘制图，以及同一路径在 preview.120／121 的两张前后对照。原生方向键经过 Activity 的正常分发；没有替换产品的焦点路由或滚动实现。普通状态刷新不拉回手动滚动的位置，转到搜索后也不会显示旧行。

原始失败、两次探针包、第一次未生效的候选、修正后的最终包及日志均保留在 D:\RHRemoteTools\ui-workspace-scroll121-review-20261030。baseline120-unit.xml 记录原十一项中一项失败；native-layout-probe.log 与 native-animation-probe.log 分别记录立即显示成功，以及旧动画随后覆盖的完整链。

新原生路径在正式 PcView 中通过 Activity.dispatchKeyEvent 分发上下方向键，从八行设备走到末行再逐行返回，每一步核对焦点、完整可见区域、原选中设备和查询。没有用逐行 requestFocus 替代方向键；只有进入路径时设置初始目标。其他八条路径继续覆盖主导航、旧搜索输入隔离、状态更新、追加、排序、Enter／详情返回、空结果和搜索中刷新。

范围是专用 emulator-5580、应用内原生事件与自身 View.draw。设备在线状态为测试数据，没有真实串流、配对、同步、系统输入注入或 OPPO 操作；不代替物理键盘及完整 UI 目标验收。
