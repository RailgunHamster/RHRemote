## 行为调整

Moonlight 的常规屏幕逻辑主动请求横屏，因此把模拟器改为窄尺寸并不能证明 Game 运行于竖屏。RHRemote 的桌面会话现在遵循系统旋转设置，使用 FULL_USER；启用屏幕手柄时保留上游原有的方向规则。配置变化时取消尚未完成的触控，释放按键和延迟手势，避免沿用旧坐标。

修改通过 `tools/prepare-android.ps1` 的明确上游锚点接入，没有整体替换 Game 的方向方法，后续合并上游时锚点不匹配会停止。没有改变编码、码率、解码器或传输实现；Release 的两份原生库与 preview.77 字节哈希一致。

竖屏的方向键仍在右下，Tab 在左侧偏上。远程使用既有 1920×1080 物理桌面，客户端保持其比例，因此竖屏有上下留白。本轮没有改变主机物理屏幕分辨率，也没有验收虚拟屏跟随旋转变更桌面尺寸。

四向滑动只产生对应轴的滚轮消息，没有产生拖动按钮。默认方向是上划为垂直负值、下划为正值，左划为水平正值、右划为负值；每轮结束 mouseDown=mouseUp=4，middleDown=middleUp=1，中键未保持按下，修饰键为 0。反转滚动和实体触屏仍不在本轮实测范围内。

landscape06 在保留同一 Game Activity、同一统计记录及连接的情况下改变模拟器窗口尺寸，并核对竖屏窗口、旋转后至少三次新的 render_submit 和非黑解码 Surface；实际取得五次新的提交。随后继续验证全部悬浮按键，最后核对同一竖屏下“控制／收起”的位置一致。该证据来自系统配置变化和实际应用窗口，不是只改图片尺寸；物理传感器与 OPPO 效果仍待实机验收。
