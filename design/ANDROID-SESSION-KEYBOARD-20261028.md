# Android 会话弹窗按键与回调归属

本地 Android `0.2.11-preview.38 / 262`，Windows 保持 preview.47。只读显示枚举仍为主屏和无名称虚拟屏，本轮未启动桌面预览，OPPO 未操作，未发布。全程使用共享动作、应用内部 Dialog／Button 派发和自身绘制图，没有 computer use、OS 输入注入或系统截图。

## 复现与修复

SDK 28 的生产会话控制器回归中，Esc 无法关闭快捷键菜单或取消断开确认，两项明确失败。API 35 模拟器的旧 APK 不同：应用内派发时菜单已关闭，按下被处理，抬起返回未处理；原生整条测试因此失败。不能将其描述为所有 Android 版本都无法关闭。

快捷键、错误详情和断开确认现在消费 Esc 按下／抬起，在未取消的抬起时调用已有 `stream.menu.close` 或 `stream.exit.resolve(choice=stay)`。重复按下不关闭，被取消的抬起保留弹窗。非 Esc 键的分发不变，没有第二套会话业务逻辑。

补查弹窗替换场景，初次修复的回归明确失败于“旧 Esc 关闭新菜单”。现在按键、按钮、列表项及取消事件都核对所属弹窗和控制器是否仍有效，再进入共享动作。过期事件不会关闭新菜单、取消新的断开确认或发送旧菜单中的快捷键。

最终 290 项单元测试通过，覆盖浅深菜单、返回、Esc 正常／重复／取消，以及替换后的旧按键、按钮和取消回调。

## 实际串流复验

无窗口 emulator-5580 使用已有身份连接 winserver，临时参数为 1920×1080、30 帧、H.264、6 Mbps、静音和模拟器软件解码对照，退出后恢复。该设置用于 UI 验证，不替换默认 25 Mbps，也不代表动态画面帧率验收。

最终 `native38-light03` 和 `native38-dark02` 两条完整原生流程通过，均取得自身视频 Surface 的非黑画面：

- 快捷键、错误详情、断开确认的 Esc 均处理按下／抬起，按下后弹窗保持，抬起后关闭，连接保留。
- 应用内给“关闭”“继续连接”按钮聚焦并派发 Enter，经共享动作完成对应操作。
- 新菜单和新断开确认保持打开，旧弹窗的 Esc、按钮、取消事件没有影响它们，当前按钮仍可正常关闭。
- 既有分类、静音音量、统计、模式／移动画面／缩放 API、主题、返回确认、主动退出和回到设备页继续通过。

这些键只派发给自身 Dialog／Button，不代表 ViewRoot／系统键盘路由、Tab／方向键导航或真实外接键盘验收。本轮没有切屏、移屏、发送有效远程快捷键／安全注意序列或播放声音。
