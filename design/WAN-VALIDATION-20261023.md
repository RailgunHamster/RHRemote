## 实际串流

Windows → winserver，H.264、1920×1080、目标 30 FPS、声音关闭。统计从连接动作开始计时，包含选路；Windows 的 render_return 表示 CPU 渲染调用返回，不代表物理屏幕扫描完成。

| 路径 | 选路及启动原生进程 | 协议就绪 | 首帧 render_return |
| --- | ---: | ---: | ---: |
| 局域网 | 21.78 ms | 1601.83 ms | 2110.97 ms |
| 强制自建中继，第一次 | 441.73 ms | 3448.80 ms | 3806.03 ms |
| 强制自建中继，另一次 | 380.13 ms | 4593.17 ms | 5002.89 ms |
| 内置直连 | 407.00 ms | 1487.34 ms | 1751.97 ms |

上表为 TCP 通道确认优化前的记录。随后发现每个代理 TCP 通道先等一轮确认才发送原生请求，多增加一次 RTT。改成把原生请求与通道头一起发送，主机仍在通过授权检查后才连接 Sunshine。真实 QUIC 回归测试要求“先收到请求才能回复确认”，确保不会退回到原来的串行等待。

同一自建中继路径的 7 条 RTSP 请求总和由两次基线的 829.84 / 774.26 ms 降至三次复测的 482.71 / 470.56 / 459.84 ms；三次复测首帧 render_return 为 3630.33 / 3549.65 / 3623.28 ms。探索过程中也测到过 6767.34 / 4466.29 ms，不能宣称首帧已稳定在 3.6 秒：其中一次 HTTP resume 占 2269.66 ms；显示准备中的 D3D 创建达到 640–847 ms、销毁达到 507–925 ms，仍需继续分析。

测试曾把上一段会话残留的 firstFrame 当成本次结果，已丢弃该无效样本。新连接会立即清空旧统计，并补入现有并发连接回归；实机测试还根据本次独立 trace 中的 render_return 核实首帧。

第一次中继记录 4519 帧，约 118 秒，渲染调用返回平均 38.36 FPS，帧间隔 P95 为 30.08 ms、最大 76.25 ms，缺失帧号 0，记录到 1 次丢帧。这一段主要是桌面内容，不能当作持续高运动场景或固定 30 FPS 节奏验收。主机原配置 minimum_fps_target=60 高于客户端目标，输出帧率会超过请求值；本轮未修改该配置。

OPPO → winserver 已通过强制自建中继接收 2520×1680 视频。中继模式关闭该传输端的 IP 直连，所有候选仅启用 relay，不依赖 Tailscale 地址。动态图形测试中的短窗渲染约 27–30 FPS，网络丢帧显示 0%，网络延迟约 54–59 ms；主机使用现有软件编码配置。主机自有测试窗口核对 primary_down/up=2/2、secondary_down/up=1/1、wheel_delta=120、drag_moves=1、held=0。全程声音关闭，不能当作音频验收。

OPPO 首个中继统计的 surface_render_callback 约 3066 ms，但该旧候选在选路完成后才开始统计，不包含前面的约 358 ms 选路。已调整统计起点，新的代码只完成编译，实机复测按用户要求暂停。

以上两端当时均在家中局域网。经公网 tc 强制中继的实际视频已确认，但这不能代替不同运营商、蜂窝网络、Wi-Fi 切换或受限网络的验收。

## 发现与处理

- 本机断开的 WLAN 2 仍保留 192.168.0.114，与 OPPO 地址冲突，本机路由选择到了本地地址。经 winserver 转接 ADB 后确认 OPPO 型号，无需修改网卡或 IP；暂停测试时调试连接已断开。
- 固定的 57984–58010 代理端口落在 Hyper-V TCP 预留范围，Windows 返回 10013。改成自动尝试完整端口组，测试与实际 Windows 中继已通过；不改系统预留范围。
- ENet 绕过原生 SET_PORT 宏，需要单独适配控制 / RTSP 端口；其 MTU 也限制为 1024。主机 UDP 使用动态源端口，Sunshine 通过有效 PING 学习实际来源。
- Windows 每个原生串流进程重新建立代理映射；运行串流期间设备探测不替换当前通道，实际启动环境显式采用本次选择的偏移。
- HTTP 统计补丁旧备份缺失时改为明确失败，实际 Windows 连接中已观察到 22 个 http_transport 事件。Windows / Android 源码也已加入选路阶段事件。
- winserver 首次部署曾报回滚异常；核对旧服务、UUID 和规则仍正常后，从干净阶段重试安装成功。安装日志已改为完整收集子进程输出，安装器也保留原始错误，避免只看到回滚错误。原始首次安装异常的具体原因未确认。
