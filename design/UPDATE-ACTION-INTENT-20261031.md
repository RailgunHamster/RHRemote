# 更新主按钮的操作与安装包归属

2026-10-31，本地候选 Windows／Android `0.2.11-preview.148`，Android versionCode `366`。继续沿用已选的设置布局与单主按钮，不增加检查、下载、安装三套独立入口。

## 修复的问题

Android 原更新按钮在点击排队期间读取最新状态。按下“检查更新”后出现候选版本，旧点击会直接下载；同版本换了附件，旧按压也会下载新附件。三个原行为失败用例保存在 `D:\RHRemoteTools\ui-update-intent148-review-20261031\android-red-01.log` 与对应 XML。

两端 API 增加可选 `expectedIntent`，主按钮始终携带当前 `updates.intent`。快照包括动作、任务编号、可用版本、是否已就绪和安装包身份。先校验快照，再做草稿导航确认、任务准入和网络操作。Windows 处理来自平台的实时快照，不能验证新版后仍用控制器旧缓存决定动作；下载准备完成后继续安装也保留明确的快照。旧无参 API 保持兼容。接口见 [API](API.md)。

Android 主按钮和取消按钮复用设备页已验证的 `RhBoundAction.Button`。按下时保存参数，绑定改变、禁用、隐藏或移除后取消旧按压；取消按钮固定任务编号。说明、镜像或进度改变不替换安装包身份，正常点击继续执行。主按钮仍按状态显示检查／下载并安装／安装更新，取消仅在任务执行期间出现。

## Windows 缓存与目标选择

检查了仓库锁定的 Velopack `1.2.110-ge826545` 源码：`download_updates()` 遇到同名最终文件直接返回，不验证已有文件；`get_update_pending_restart()` 返回最新本地包。原客户端又把任意本地就绪包当成当前远端候选已就绪，可能显示 B 却安装 A。

选定远端附件后，使用包名、版本、类型、文件名、长度和校验值识别目标。缓存必须通过长度和 SHA-256 核对，旧索引保留 SHA-1 回退；失配的指定缓存文件才可重新下载。安装直接使用所选附件并再次核对。只存在历史离线缓存、尚未取得远端索引时，保留原离线安装行为；该路径没有新增或声称取得远端校验值。

缓存哈希和修复在更新工作线程执行，启动与页面刷新不读取整包。有效缓存可直接复用，不重新下载。检查只读取索引并核对已有缓存，不启动 APK／安装包下载。

## Android 首次布局的底部按钮

真实模拟器检查发现另一处问题：首次显示更新页时，ScrollView 的 layout 回调直接修改同级页脚的 padding。页脚采用了新留白，内部按钮行仍保留旧测量宽度，导致按钮整块落在裁剪区外。

原生失败记录 `android-native03.log` 中，页脚宽 1404 px、左右 padding 各 162 px，但按钮行仍宽 1356 px，目标按钮起点已超过父容器的内容边界。现在在本次 layout 完成后应用新的横向边距，让 Android 重新测量同级页脚。最终检查同时断言按钮完整可见的宽度和高度。
