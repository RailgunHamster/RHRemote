## 记录契约

新增独立 `rhremote_frame_trace` 辅助模块，尽量将维护改动集中在 RHRemote 自有文件，便于合并 Sunshine 上游。
只记录时间、编号、状态与字节数，不记录画面、声音、输入内容、证书或认证信息。
每次测试启动通过已配对的 launch / resume 请求携带一个可选统计标记和受限字符的客户端统计编号。
普通模式不生成逐帧文件；旧服务端不识别标记时仍正常连接，客户端显示未获得主机统计。

主机在建立实际流会话时创建独立追踪对象，使用原子创建的新目录保证编号不冲突，不使用客户端输入作为文件路径。
对象通过视频配置、编码上下文和编码包共享，保留到该会话的最后一份记录释放，跨重连即使 frame=1 也不会拼接。
不要使用 `channel_data` 指针地址作为长期会话编号。

每条事件至少包含主机追踪编号、客户端统计编号、主机单调时钟、阶段、编码帧号、捕获编号、编码包编号、
是否读取了新捕获、来源时间是否已知、结果及相关计数。需要下列实际事件：

- 捕获完成：在两个 capture 回调中为新图像赋捕获编号，保存已有 `img.frame_timestamp` 和回调时间。
  原时间是桌面来源呈现时间的换算值，不是应用绘制完成或物理扫描完成；未知时保留未知，不填当前时间冒充。
- 转换开始／结束：异步与同步编码路径均记录。未取到新图像时保留上一次来源编号并明确标为重复输入。
- 编码提交／调用返回及编码包输出：覆盖 AVCodec 与 NVENC。根据实际输出 PTS 查找原提交元数据，
  使用有上限的映射并报告淘汰／未知，不将旧输出绑定到当前帧；不只记录成功输出。
- 发送开始／结束／异常：包携带来源元数据及独立包编号。记录编码队列等待、实际 RTP 90 kHz 时间戳、
  FEC、实际 pacing 等待、发送调用耗时、分片及字节数。只把终点称为发送调用返回，不能写成客户端收到或显示。
  重复帧标记在修改回退 RTP 时间戳之前保存，不能被第二个 FEC 块误改。

生产线程只写固定容量的元数据队列，不在捕获、编码或发送线程写磁盘。队列满、文件上限或磁盘失败均明确报告，
不阻塞串流或伪装成完整统计。单文件建议上限 64 MiB，保留 `trace_end` 和丢记录／截断计数。
路径、启用状态和统计失败通过状态输出可见；文件失败不应导致远程连接失败。

## 分析与验收

分析器按“追踪编号＋帧号／包号”关联事件，核对缺失阶段、重复输出、未知 PTS 和不完整尾部。
可以计算主机各阶段及间隔，但不能直接减不同机器的时钟得到网络延迟；来源 RTP／帧号对齐也不等于时钟已同步。
报告保留重复输入数量，不将额外编码次数当作独特画面 FPS。
分析成功保存摘要、必要帧表和时间线后，按既定规则清理不再需要的原始文件；仍用于定位的原始记录保留。

必要回归包括：两个新会话都从帧 1 开始仍隔离、编码输出乱序／延迟／同 PTS 多包、未知与被淘汰元数据、
队列满、文件上限、写入失败、正常排空、带错误的关闭尾部、关闭测试模式不产生文件、launch 与 resume 传递、
新旧主机兼容，以及分析器对缺失数据拒绝完整结论。

在 Windows MSYS2 / UCRT64 和 `test_sunshine` 中验证后，完整构建并部署到允许测试的主机。
Windows 客户端使用主屏做静音 1080p30 的局域网／中继自然视频对照，核对实际编码包、RTP 和客户端帧编号，
结束后恢复用户参数与屏幕布局。OPPO 自动测试仍暂停，不能用 Windows 结果替代 Android 或实际蜂窝网络验收。

## 使用分析器

先结束测试连接，等待主机文件出现 `trace_end`。从该客户端编号对应的主机生成目录收集
`frames.jsonl`，保留主机目录名（`trace_id`），不要把两个会话的同名文件拼接。

```powershell
python tools/analyze-host-frames.py D:/RHRemoteTools/host-traces/<trace_id>/frames.jsonl
python tools/analyze-statistics.py <client-run-folder> --host-frame-trace D:/RHRemoteTools/host-traces/<trace_id>/frames.jsonl --keep-raw
```

第一条用于单独分析，第二条用于导入客户端离线报告，也可在已有报告上加 `--refresh-report`。
导入前核对 `client_id` 等于客户端运行目录名；同一次运行的多份主机记录可重复传入参数，仍保留独立时间线。
已完成单独分析并删除原始文件时，应保留分析产物；若还需要导入客户端报告，第一次加 `--keep-raw`。

输出 `summary.json`、`frames.csv`、`packets.csv`、`timeline.json`。时间线可以导入 Perfetto，
含主机单调时钟下的实际事件和调用跨度，不伪装为已经与客户端时钟对齐。
只有完整、未变化且路径符合主机生成目录契约的原始文件才会在所有分析产物持久化后自动删除；
文件名不符合契约、指定 `--keep-raw`、缺少阶段／尾部、记录溢出、文件封顶或写入失败时保留原始记录。
转换预热、重复输入、同 PTS 多个输出和编码器代次均单独处理；不会把编码包数量当作独特画面帧率。
