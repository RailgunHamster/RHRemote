# Windows 表单控件刷新与草稿归属

当前本地候选为 Windows preview.133，Android 仍为 preview.129。日常 preview.101 已按用户确认完成升级且保持关闭，本轮没有替换日常客户端或公开发布。

## 已复现的问题

preview.132 只修复了搜索框。继续用实际 Slint 控件编辑后，再从外部更新模型，另八个输入框仍保留旧文字：添加地址、设备别名、WebDAV 地址和用户名、首选地址、备用地址、中继地址、数字参数。五类有状态控件也存在同类问题：自动同步勾选、同步间隔、路径勾选、配置下拉框、串流音量。

证据目录为 `D:\RHRemoteTools\ui-form-rebind133-review-20261030`。`baseline-editors02.log` 和 `baseline-stateful.log` 分别保存八项和五项旧版失败；不是只检查顶层属性。测试聚焦同一个实际编辑器、执行按键、回送模型、替换值，再检查后续真实回调。旧输入框发出 `alpha  ` 而非 `beta `，旧音量框发出 42 而非 91。

原因是控件的文字、勾选或选中值采用单向绑定，首次用户操作覆盖绑定，后续模型刷新无法更新保留的控件。

## 修正

- 将已确认的输入和选择值连成双向绑定，保持原控件实例和焦点；密码仍使用原有按草稿代次清空的规则，不从状态中回填。
- 搜索、添加地址、别名、WebDAV 编辑，以及配置输入、步进、选项和路径编辑，在 UI 回调内通过原 Controller 立即验证并更新内存草稿。仅明确列出的本地动作进入该分支；保存、同步、连接、更新和原生音量命令继续走异步队列。
- 配置动作先捕获来源草稿 ID，再进入同一参数映射和控制器校验。旧草稿的编辑继续被拒绝；两次布尔切换均读取当时的实际草稿。
- 配置模型同时核对控件临时值。即使新旧草稿内容相同，旧来源的选择被拒绝后，也会还原正确选项，随后可继续编辑。
- 路径行增加只由控制器状态计算的 `toggle-blocked`。最后一条启用路径不可关闭，关闭中的其他行和未启用行不因自身临时勾选而错误禁用。现有最后路径、排序边界和重复点击断言保留。

## 验证范围

`full-rust-tests04.log`：Core **136**、UI **248** 项通过，零失败；另 **4** 项既有专项用例保持忽略。

新增回归覆盖十三类控件刷新、八个输入框连续输入与逐次 MainView 回读、外部替换后继续输入、旧草稿选择还原，以及即时编辑不调用平台、不写配置文件。保存、真实同步、连接及音量命令均不能进入即时草稿分支。

最终 Portable 在实体 C3273IUY / DISPLAY2 浅深两主题通过 **401 个检查点、24 个表单控件场景**，见 `native-current02/verification.json`。每主题包括八个输入框和四个勾选／下拉控件；同一输入框连续三个空格后由外部替换文字，再继续输入并取消。每个控件请求核对副屏位置、窗口未激活及没有系统输入注入。测试通过实际控件接口操作，没有 computer use。

串流音量本轮仅通过真实 Slint 控件与明确的会话模型替身验证，没有建立远端连接或播放声音；不作为实际音频验收。系统物理键盘、UIA、OPPO、完整串流及新版本安装／公开交付仍保留各自验收范围。

## 保留的失败

首次完整回归发现路径勾选修改了用于判断自身可点性的值；修正为独立限制后重跑。新增模型字段最初遗漏了一个测试和视觉样例的初始化，编译器拒绝，补齐字段后完整通过。早期本地分支测试把编码值误写为 `h264`，按原有效值 `H.264` 修正夹具，未放宽产品校验。

第一次副屏流程在取消时被接口拒绝：页头和页脚有两个同动作入口，脚本没有指定唯一控件。该次不是通过；记录保存在 `native-current01`，其隔离配置已还原、窗口已关闭。脚本改为精确选择底部“取消”后，使用同一最终 Portable 完成第二轮，没有改动产品或放宽文字断言。
