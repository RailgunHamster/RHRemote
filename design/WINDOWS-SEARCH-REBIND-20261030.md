# Windows 搜索框重置与按键重复

最新本地候选为 preview.132，包含 preview.130 的弹窗空格确认、preview.131 的按钮按键重复过滤，以及本轮搜索框绑定修正。日常 preview.101 未替换，候选未发布；Android preview.129 与 OPPO 未操作。

## 搜索文字残留的实测原因

preview.131 在实际副屏窗口的第二轮编辑失败：先把查询设为 `test`，按 End、重复 Left、重复 Space，实际得到 `tes  t`，而预期为 `tes t`。焦点确实在搜索框，Left 没有触发业务命令，Space 只发出一次 `devices.filter`；不是多次提交同一按键。两次完整样本保留在 `D:\RHRemoteTools\ui-key-repeat131-review-20261030/native-current01`、`native-current02`，后一轮有失败时的状态、各按键回执和应用自身绘制图。

随后新增同一编辑器的回归：第一次编辑后回送模型结果，再从外部清空并重新设查询，第二次继续编辑。旧版同样返回两个空格，见 `D:\RHRemoteTools\ui-search-rebind132-review-20261030/baseline-reset-test.log`，明确失败于第二轮。

原搜索框的文字是模型到控件的单向绑定。首次用户编辑会覆盖该绑定；此后外部重置改变模型，却没有更新保留的编辑器文字。再次移动光标和插入空格时，操作的是旧文本。

preview.132 将 MainWindow → DeviceListPane → LineEdit 的查询值连成双向绑定。同时仅对 `devices.filter` 这一项纯本地输入，在 UI 回调中立即调用原 Controller，让本次编辑先提交状态，再接受后续模型刷新；其他动作继续使用原工作队列。地址长度、未保存确认和安装阶段等控制器校验保留，不调用网络或持久化接口完成搜索。

## 按钮自动重复的前置修正

preview.130 的独立副屏窗口实际收到一个 `repeat=true` 的 Space，就切换了一次主题。该反例、原主题及配置还原保存在 `D:\RHRemoteTools\ui-key-repeat131-review-20261030/baseline-native.json`。

preview.131 起，自绘按钮、侧栏、设备行和选择菜单行消费但忽略重复 Enter／Space，正常按下仍执行一次。没有把全部重复事件禁用；编辑框中的重复空格及方向键继续交给原控件。四类实际 Slint 控件、两种按键各三次重复和正常确认的回归通过，选择菜单使用明确的会话模型替身，没有网络串流。

这轮 preview.131 的完整实际流程仍因上述搜索框残留而失败，不能写成全轮通过。最初的软件用例还因未展开控制栏被正确拒绝打开菜单；补齐已有“打开快捷键”动作后通过，没有改动产品的会话准入规则。
