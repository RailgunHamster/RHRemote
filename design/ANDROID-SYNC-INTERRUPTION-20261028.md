# Android 同步中断后的反馈（preview.41）

原来的同步忙碌、错误和任务编号只在进程内保存。应用进程结束后，新实例回到 idle，界面无法区分“尚未同步”和“上次任务未完成”。新增两项回归在 preview.40 代码上复现这一点：9 项同步任务测试中 2 项失败，原 7 项通过。

## 行为

- 每次提交同步前，用应用私有 SharedPreferences 持久化 pending、任务编号和开始时间；不保存密码、账号、设备配置或同步内容。任务完成并处理本机结果后才清除 pending。
- 新进程发现 pending 时，显示“上次同步已中断，传输结果未确认。自动同步已暂停，请手动同步核对”，状态为 `phase=interrupted`、`busy=false`、`automaticBlocked=true`。
- 不恢复旧 worker 或旧冲突选择。定时检查跳过自动同步，自动 API 请求返回 `skipped=true, reason=sync_interrupted`；用户仍可浏览、编辑或手动同步。
- 表单编辑、取消、保存设置及主题重建保留这条提示。明确手动同步进入新请求，或移除同步设置后清除中断状态；同一进程中的普通网络错误仍使用原有重试和提示逻辑。
- 开始时记录失败不入队、不联网；完成状态写入失败仍保留核对提示和自动同步暂停。异常元数据类型不会使设置页崩溃。

## 验证

最终 306 项单元测试全部通过；同步任务类 13 项，覆盖冷实例恢复、连续重开、编辑保留提示、自动请求拒绝、手动重试、任务记录写入失败、完成记录失败和元数据异常。

无窗口模拟器 `emulator-5580` 上完成两条实际进程终止流程。测试先通过正式 RhSyncWork 提交任务，保持 worker 在测试队列内，确认任务记录已落盘且应用进程仍存活；随后只结束 `com.rhremote.client`，核对该 PID 消失，再启动新进程。

## 范围

测试没有执行 WebDAV 传输或自动重放，也没有新建 WebDAV fixture；工作线程留在队列内。它证明排队任务在实际进程终止后的反馈和暂停，不替代真实 WebDAV、PUT 已返回或本机应用配置期间被终止的验收。API／服务器可用性及跨客户端合并继续保留在 TODO。

持久记录只发生在每次同步开始及完成，不进入视频逐帧路径。两次不含 UI 重建的任务注册观察值为 22.20／21.95 ms，不是完整按钮响应或 OPPO 的存储延迟验收，不声称性能改善。
