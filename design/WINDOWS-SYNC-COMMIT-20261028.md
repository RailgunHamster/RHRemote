# Windows 同步完成顺序与错误反馈（preview.48）

原 Windows 后端在 PUT 返回后立即保存新 base／lastSyncMs，控制器随后才写本机偏好；本机保存失败又通过 `?` 返回，未保留同步页错误。完成标志也早于设备状态恢复。三个无网络回归在原顺序上失败：基准提前推进、新实例重试丢失远端新名、本机写入失败没有可操作的错误提示。

## 行为

- PUT 后保持原基准和成功时间，记录私有 pendingApply 与当前待应用结果。pendingApply 不包含密码或额外同步内容；重开后显示结果未确认并暂停自动同步。
- 控制器依次保存并回读本机偏好、恢复设备状态，再调用平台内部的完成确认。确认核对实际共享配置和账户快照，之后才写入基准及成功时间；最终记录回读通过后才发布同步完成状态。
- 任一收尾步骤失败都结束忙碌、显示对应错误并暂停自动同步；基准写入前的失败保留旧基准，写入后回读不确定也不会宣告成功。本机已经写入的新配置不会因完成记录失败而被回滚；后续手动重试重新读取远端。旧结果不能重新创建已移除账户。
- 应用、刷新设备、保存完成记录三个阶段有独立按钮文字；完整完成前保持忙碌，重复请求被拒绝。“上次同步已完成”明确表示历史状态，不把旧记录作为本次结果。后台结果不覆盖更新／外观等其他页面的状态。
- 自动同步暂停时，API 返回 `skipped=true, reason=sync_interrupted`。编辑、取消和返回同步页保留核对提示；确认成功或移除设置后解除该状态。
