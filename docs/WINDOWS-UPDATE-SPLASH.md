# Windows 更新过渡窗口

此功能由 0.2.20 及后续客户端发起更新时使用；从更早版本升级到 0.2.20 的交互仍由旧客户端负责。

设计和绘制源码来自用户提供的 `results/velopack-update-ui/` 接入包。项目保存经过审阅的 `RHRemoteUpdateSplash.cs`；没有采用接入包中的预编译 EXE。

Windows 构建使用系统 C# 编译器编译辅助程序，并将生成的二进制与统一图标嵌入 Rust 客户端。用户机器不需要编译器。更新包下载和校验完成后可预先释放资源；每个客户端进程使用全新随机目录，辅助程序不从可预测的旧 EXE 缓存启动，也不在安装目录中驻留。

在提交更新前启动独立过渡窗口。成功启动时让 Velopack 静默替换；辅助窗口不可用时保留原来的 Velopack 提示。更新程序立即启动失败时，Rust 的退出守卫通过取消文件关闭过渡窗口，原应用继续显示更新失败反馈。仍由现有控制器完成草稿确认、所有会话关闭检查和正常退出，不调用 `process::exit` 绕过这些流程。

过渡窗口保留旧进程的原始句柄；只接受当前安装根目录 `current/RHRemote.exe` 且在本次更新开始后启动的新窗口。另一个安装、历史版本、原生 `engine/RHRemote.exe` 或 PID 复用都不能完成交接。阶段显示是对更新进程和临时目录的观察，不作为解压字节百分比或精确耗时统计。

测试接口：编译后的辅助程序支持 `--self-test` 进行无窗口的路径归属检查；`--screenshot <path> --demo-stage 1|2|3 --theme Light|Dark` 在隐藏表面绘制 PNG；`--monitor \\.\DISPLAY2` 可用于显式副屏演示，找不到指定显示器时结束而不回退主屏。
