# Windows 多会话

设备主窗口保持设备列表与设置。点击连接后，一个专用 RHRemote 窗口持有该设备的原生串流进程、控制接口、悬浮控制条、键盘与重连循环。不同服务器可以并行；同一服务器按 UUID 复用已有窗口。

每个会话拥有随机会话 ID、独立鉴权令牌、动态绑定的本机 API 端口、状态文件、统计目录和原生引擎配置快照。快照保留已有的客户端证书与配对关系，不写回主身份库。不能把原生 QSettings 文件直接在多个活跃进程之间共享：上游 ComputerManager 会替换整个 hosts 数组，旧窗口可能覆盖新配对。

浏览器监督各自的原始 Child 句柄。控制请求必须同时匹配存活进程、会话 ID、设备 UUID 和本机 API 身份，不能仅根据缓存端口转发。不同会话的慢请求分别执行；关闭和断开不被同一会话的普通控制队列锁住。

主窗口关闭时向所有子窗口发送关闭请求，等待各自原生清理完成后退出。子窗口还监视父进程持有的 stdin 管道；父进程退出或异常结束时，EOF 请求子窗口按正常清理流程关闭。不会通过机器名、进程名或可能复用的 PID 结束其他进程。

主窗口负责配置同步、代理与更新。子窗口不能打开另一份设备编辑界面；返回设备会关闭本会话并回到原主窗口。键盘布局与快捷浮钮偏好只提交实际修改的字段，避免旧配置快照覆盖主窗口的新设备、顺序或配置。远程连接参数仍按设备保存。

## 控制 API

使用现有 `POST /v1/action` 与 Bearer 鉴权。所有端口仅监听回环地址，拒绝浏览器 Origin 请求。

- `device.connect {uuid}`：验证配对、身份、草稿与窗口来源后创建或复用会话，返回 `sessionId`。
- `session.list {}`：读取窗口摘要。`GET /v1/state` 的 `desktopSessions` 也提供同一状态。
- `session.activate {sessionId}`：切换到对应远程窗口。
- `session.close {sessionId}`：关闭该窗口，等待它自身的清理。
- `session.action {sessionId, action, args}`：向指定窗口发送串流控制、重连或截图操作。例：`{"sessionId":"…","action":"stream.audio.volume","args":{"volume":25}}`。

`stream.*`、`connection.retry` 和已有的窗口截图操作继续使用原控制器校验。会话窗口的鉴权信息不会出现在设备列表或同步文档中。`session.preferences` 是用于同步本机键盘偏好的父子进程操作；不接受设备列表、连接参数或凭据补丁。
